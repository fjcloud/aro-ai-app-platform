= Showroom for the ARO Workshop

This repository is the ARO version of the AI-powered developer platform workshop.

The subscription starts empty. `make deploy` creates an Azure Red Hat OpenShift cluster with a hosted control plane. Act 1 publishes DeepSeek-V4 Pro on Microsoft Foundry and points Dev Spaces at it. Act 2 ships an app with that endpoint. Instruction pages are in `content/modules/ROOT/pages`.

The cluster steps follow link:https://github.com/fjcloud/aro-hcp-quickstart[`fjcloud/aro-hcp-quickstart`]: customer resource group, managed identities, a customer-managed etcd key, Entra ID for the console, and a Red Hat pull secret. This workshop publishes the API and the ingress, so `oc`, Dev Spaces, and application routes work from the machine that ran `az login`. The quickstart keeps both private and publishes only the console.

== Prerequisites

* `az login` against the subscription that should own the cluster
* The `aro-hcp` CLI extension. The browser terminal already has it. `az aro hcp cluster create -h` shows `--operators-authentication`. Do not install the published `aro` extension; that build hides those flags.
* `oc` on `PATH`
* Permission to create Entra app registrations in that tenant
* A Red Hat pull secret at `~/pull_secret.json` (override with `PULL_SECRET_FILE`). It must contain `registry.redhat.io`, `registry.connect.redhat.com`, and `cloud.openshift.com`. It is not written into this repository.
* Quota in `eastus2` for the workers: *Standard DSv3 Family vCPUs* at least 8 (two `Standard_D4s_v3`). The workshop model is Foundry Global Standard. It does not need a GPU quota.

The same flow is in the browser at https://aro-terminal-fja.azurewebsites.net/. *Create* starts an Azure CLI container in the lab resource group and attaches the terminal on the page. It signs in as the service principal. Paste the deploy command into that terminal.

== Use

[source,bash]
----
make deploy
export KUBECONFIG="$PWD/state/kubeconfig"
make status
make delete CONFIRM=yes
----

`make deploy` can be run again. It leaves existing infrastructure in place and finishes any step that did not complete.

`make deploy` creates:

[cols="1,2", options="header"]
|===
| Piece | Value

| Region
| `eastus2`

| Cluster
| `aro-ai-eus2`, OpenShift 4.22

| Workers
| `workers`, 2 × `Standard_D4s_v3` (4 vCPUs each)

| API / ingress
| Public / Public

| Console login
| The Microsoft account that ran `make deploy`. There is no kubeadmin password.

| etcd
| Encrypted with a customer-managed key
|===

`state/cluster.env` and `state/kubeconfig` are generated locally and gitignored.

Lab 1.1 creates a Foundry account and a `deepseekv4pro` deployment of DeepSeek-V4 Pro (Global Standard, pay per token). Lab 1.3 stores that endpoint in the Dev Spaces secret. Do not run `make gpu` for this workshop.

Sign in to the console URL from `make status` with the same Microsoft account that ran `make deploy`.

`make delete CONFIRM=yes` deletes the cluster, both resource groups, the soft-deleted Key Vault, and the Entra applications.
