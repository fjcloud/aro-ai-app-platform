= AI Developer Platform on ARO

Start with an *existing ARO cluster* and a WeTTY bastion from Red Hat Demo Platform. Cloud SSAs use this guide to prepare access and lead participants through the platform and developer roles.

== Run the workshop

. Prepare and assign an RHDP environment with a ready classic ARO cluster, OpenShift 4.21 or later, and a browser terminal. An Azure Blank Environment alone does not include these.
. Open https://fjcloud.github.io/cloud-terminal-pages/[Cloud Terminal], select *Azure · AI developer platform on ARO*, and enter the *workshop ID, assigned email, and workshop password*.
. The launcher retrieves the assigned Showroom URL. Shared links contain only the guide and workshop ID; each participant signs in separately.
. Follow Act 0 to clone the repository and run `make onboard` to sign in to the existing cluster.

Platform labs prepare OpenShift AI, DeepSeek through MaaS, and one T4 running
d3-mini. Developers generate *Card Scout* from scratch with OpenCode: analyze a
mixed-era card collection, browse the rarity ranking and check a price through
an OpenShift AI agent. The platform owns the dataset, read-only MCP tool, state
and MLflow traces. The generated Go app is a small UI and same-origin proxy.

`make onboard` signs in using the existing ARO credentials retrieved from Azure, then detects the resource group containing that resource and writes its name, ID and subscription to `state/workshop.env`. The instructions load this file; participants do not type a resource group name or select the first group in a subscription.

Use one assigned cluster per participant. On a shared cluster, the facilitator prepares the platform once and isolates each app’s namespaces and access.

Instruction pages are in `content/modules/ROOT/pages`; Kubernetes manifests are in `deploy`.

== Architecture

[source,text]
----
Dev Spaces / OpenCode → OpenShift AI MaaS → DeepSeek on Foundry
Fixed card images → prepared Card Scout service → d3-mini on T4 → rarity ranking
Browser → generated Go UI → OpenShift AI Responses → DeepSeek + price MCP tool
Playground → same MCP tool              Model and tool spans → MLflow
Git → Tekton → Argo CD → same app
----

Use the https://github.com/fjcloud/go-app-template/tree/aro-signal-desk[Card Scout template branch]. `AGENTS.md` defines delivery rules; `APP_CONTRACT.md` defines the application and fixed APIs. The prepared service and dataset are in `examples/card-scout`; its manifests are `deploy/card-scout`, and model manifests are `deploy/decision`. The template contains no completed app to copy. Clone this workshop's `main` branch.

The platform path is: apply all operator manifests; add one D8 CPU worker and one `Standard_NC8as_T4_v3` worker with explicit MachineSet commands; enable the platform services; deploy DeepSeek and d3-mini. The developer tests D3, MaaS Chat Completions and native Responses independently from Dev Spaces with `curl | jq`, then builds the app from its contract through the existing GitOps path. Model predictions, catalogue verification and dated market references stay visible.

== Maintain the workshop

Prefer direct `oc`, `az` and `curl | jq` commands in the labs. Keep helpers for discovery, temporary identity/credential injection and dynamic MaaS/MLflow setup; define ordinary Kubernetes resources in `deploy/`.

`deploy/briefing/agent` defines the operator-managed native Responses backend in `signal-desk-dev`. Lab 1.8 supplies the cluster's MaaS URL and applies it with the CLI; the Playground UI is reserved for tests.

`make test` runs the helper and reference-app tests. `make docs` builds the guide; `make serve` previews it at http://localhost:8443.

The published d3-mini image is pinned by digest in `deploy/decision/runtime-image.txt` and `servingruntime.yaml`. The `publish decision runtime` GitHub Actions workflow rebuilds it when the pinned Dockerfile changes, or on manual dispatch. It needs the repository's `REDHAT_REGISTRY_AUTH` secret for the Red Hat base image; participants only pull the public result. After validating a replacement on a T4, update both digest references together.

`examples/card-scout/data` freezes 48 cards across eight eras and three controls.
Input image hashes and held-out reference labels are separate. The Card Scout
platform image embeds the verified images, avoiding session-time image downloads.
Its publishing workflow uses the public workshop runtime package with a separate
Card Scout tag; `deploy/card-scout` pins its digest. The app contract prohibits
copying a completed implementation into the generated app.

`content/` contains the guide, `deploy/` the active platform/model manifests, `scripts/` the setup helpers, and `e2e/` the validation scripts and current evidence. `docs/index.html` preserves the old terminal link as a redirect to Cloud Terminal.

Retired terminal hosting, HCP provisioning and GPU experiments remain in https://github.com/fjcloud/aro-ai-app-platform/tree/e333ecdf5aef0946cf747d7a970b6b386ce87835[the pre-cleanup revision].
