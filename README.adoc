= AI Developer Platform on ARO

Start with an *existing ARO cluster* and a WeTTY bastion from Red Hat Demo Platform. Cloud SSAs use this guide to prepare access and lead participants through the platform and developer roles.

== Run the workshop

. Prepare and assign an RHDP environment with a ready classic ARO cluster, OpenShift 4.21 or later, and a browser terminal. An Azure Blank Environment alone does not include these.
. Open https://fjcloud.github.io/cloud-terminal-pages/[Cloud Terminal], select *Azure · AI developer platform on ARO*, and enter the *workshop ID, assigned email, and workshop password*.
. The launcher retrieves the assigned Showroom URL. Shared links contain only the guide and workshop ID; each participant signs in separately.
. Follow Act 0 to log in to the existing cluster, clone the repository, and run `make onboard`.

Platform labs require cluster-admin access and an Azure identity with permission to create Foundry resources in the exact assigned resource group. OpenShift AI MaaS publishes DeepSeek on Foundry for OpenCode, with a separate MaaS key and token quota (external models: Technology Preview). RedHatAI Whisper Large v3 Turbo INT8 runs on one T4 through OpenShift AI and Red Hat AI Inference. The same sample app becomes *Cluster Voice*: speak or type a question, then let a read-only agent inspect internal monitoring metrics and answer with evidence. The Playground tests its MCP tools; MLflow traces its model and tool calls.

`make onboard` detects the resource group containing the connected ARO resource and writes its name, ID and subscription to `state/workshop.env`. The instructions load this file; participants do not type a resource group name or select the first group in a subscription.

Use one assigned cluster per participant. On a shared cluster, the facilitator prepares the platform once and isolates each app’s namespaces and access.

Instruction pages are in `content/modules/ROOT/pages`; Kubernetes manifests are in `deploy`.

== Architecture

[source,text]
----
Dev Spaces / OpenCode ──> OpenShift AI MaaS ──> DeepSeek on Foundry (coding)
Browser microphone ──> Whisper (one T4) ──> editable question
Browser text ──────────────────────────────────┘
                                              ▼
Go runtime agent <──> MaaS / DeepSeek
       │      └─────> read-only metrics tools / Thanos
       │                         ▲
       └──> MLflow traces    Playground / MCP

Git ──> Tekton ──> Argo CD ──> same Go application
----

Use the `aro-transcription` branch of https://github.com/fjcloud/go-app-template/tree/aro-transcription[the app template]. ROSA keeps its existing template. A working reference app is in `examples/live-transcript`; speech manifests are in `deploy/speech`.

Allow CPU headroom for OpenShift AI, Dev Spaces and Tekton, plus quota and capacity for one `Standard_NC8as_T4_v3` worker. Lab 1.4 shows Azure CLI quota checks and explicit `oc` MachineSet commands for one D8 CPU worker when needed and one T4 GPU worker. It uses no provisioning helper or Makefile target. Classic ARO worker pools are managed through the OpenShift Machine API. The application sends independent short WAV clips for near-real-time results; it does not use a native Whisper WebSocket stream.

== Maintain the workshop

`make test` runs the helper and reference-app tests. `make docs` builds the guide; `make serve` previews it at http://localhost:8443.

`content/` contains the guide, `deploy/` the active platform/model manifests, `scripts/` the setup helpers, and `e2e/` the validation scripts and current evidence. `docs/index.html` preserves the old terminal link as a redirect to Cloud Terminal.

Retired terminal hosting, HCP provisioning and GPU experiments remain in https://github.com/fjcloud/aro-ai-app-platform/tree/e333ecdf5aef0946cf747d7a970b6b386ce87835[the pre-cleanup revision].
