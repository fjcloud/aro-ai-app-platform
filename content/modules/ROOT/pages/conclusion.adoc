== The Key Insights

*1. The cluster and the model are different bills.*
ARO HCP is the place developers edit and ship. DeepSeek-V4 Pro is a Foundry deployment. No GPU node is required for this workshop.

*2. The endpoint is OpenAI-shaped.*
OpenCode sends chat completions to `/openai/v1` with the deployment name `deepseekv4pro`. The platform injects the base URL and the key. Developers do not create Azure resources.

*3. AGENTS.md shifts governance from documentation to code.*
Platform conventions encoded in a Markdown file are read and enforced by the model at generation time. The developer gets a compliant app without opening a checklist.

*4. The same model powers the developer inner loop.*
OpenCode uses DeepSeek-V4 Pro to write the Fortune Cookie app. That endpoint is a *platform* capability.

*5. Tokens are the invoice.*
Input is $1.74 per million tokens. Output, including reasoning, is $3.48 per million. Delete the deployment when the day ends.

== What We Did Not Cover (But You Can Explore)

* *A model on a GPU node:* `make gpu` and `deploy/inference` still describe an in-cluster vLLM path. This subscription has no GPU quota, so the workshop uses Foundry instead.
* *Multi-environment GitOps:* Add `deploy/overlays/stage/` and `deploy/overlays/prod/` with Kustomize overlays; use separate Argo CD `Application` objects per environment
* *Webhook-triggered pipelines:* Add an `EventListener` + `TriggerBinding` to Tekton so `git push` triggers builds automatically
* *Application autoscaling:* Add an HPA to the Fortune Cookie `Deployment` to scale based on HTTP requests
* *ARO hosted control planes:* This workshop already runs on ARO HCP. Microsoft hosts the control plane. Worker nodes are node pools in your subscription.
