= Lab 2.2 — Test the Model APIs

== Goal

Test D3, DeepSeek and the native agent independently with `curl | jq`. Check an image prediction, a language response and a real tool call before generating the application.

*Developer · Dev Spaces terminal.* Test each capability before writing the app.
Format JSON responses with `jq`. Keep the injected MaaS key out of Git, OpenCode
prompts and the browser.

== Two models, two jobs

*d3-mini* is a multimodal decision model: it reads an image and chooses among
supplied options, returning their probabilities. Here it recognizes Pokémon TCG
cards and reads the small rarity symbol in the bottom-right corner. The prepared
platform maps circle to Common, diamond to Uncommon and star to Rare. Within
this fixed Base Set, a fully visible corner without a rarity mark maps to Common
(Basic Energy). A cropped or unreadable corner remains Uncertain.
It does not generate a description or estimate market value.

*DeepSeek* generates the Go application in OpenCode and powers the runtime agent.
The agent verifies the selected catalogue reference through a read-only MCP tool.
Its model endpoint is provided by OpenShift AI MaaS.

== Test an image on the T4

include::ROOT:partial$run-devspaces.adoc[]

[source,sh,role=execute]
----
D3_URL=http://d3-mini.decision-serving.svc.cluster.local:8080
# Set the prepared platform API URL used for images, analysis and agent-backed prices.
CARD_SCOUT_URL=http://card-scout-platform.card-scout-dev.svc.cluster.local:8080
# Ask the actual local runtime for its model ID, device and numerical precision.
curl --fail-with-body -sS "$D3_URL/v1/models" | \
  jq '{id:.data[0].id,device:.data[0].device,dtype:.data[0].dtype}'
# Download the Charizard test image from the prepared dataset.
curl --fail-with-body -sS "$CARD_SCOUT_URL/assets/item-104" -o /tmp/card-scout.png
# Encode the image bytes for the JSON request; this is transport encoding, not a model
# prediction.
base64 -w0 /tmp/card-scout.png > /tmp/card-scout.b64
# Build the D3 image-and-choices request; the file avoids embedding a large base64 string in a
# command.
jq -n --rawfile image /tmp/card-scout.b64 '{
  model:"vllm-sr/d3-mini",
  state:"Inspect the attached image and classify the card and its official printed rarity. Judge only from visible evidence.",
  images:["data:image/png;base64," + $image],
  questions: {
    "card_kind": {
      "type": "choice",
      "instructions": "Is this a Pokemon Trading Card Game card: yes or no? Pokemon, Trainer and Energy cards all count as yes. Select pokemon_tcg for yes, otherwise other_card or not_a_card. Judge the printed trading-card layout; a Pokemon illustration alone is not a card.",
      "criteria": {
        "pokemon_tcg": "A Pokemon Trading Card Game card",
        "other_card": "A card from another game, a sports card or a standard playing card",
        "not_a_card": "A receipt, photograph or object that is not a trading or playing card",
        "uncertain": "Not enough information to identify"
      }
    },
    "rarity_symbol": {
      "type": "choice",
      "instructions": "Inspect the small printed rarity mark in the bottom-right corner, beside the collector number. Report the SHAPE of this mark only. Ignore the character, its fame, the artwork, the large Energy symbols, and the 1st Edition stamp. A blank but fully visible corner is none, as on Basic Energy cards. A cropped, blurry or unreadable corner is uncertain.",
      "criteria": {
        "circle": "A small filled circle or round dot",
        "diamond": "A small diamond, a square rotated 45 degrees",
        "star": "A small five-pointed star",
        "none": "The corner is fully visible and has no printed rarity mark",
        "uncertain": "The corner or small rarity mark cannot be read reliably"
      }
    }
  }
}' > /tmp/card-scout-decision.json
# Submit the image-decision JSON and format the returned choices/probabilities with jq.
curl --fail-with-body -sS --max-time 120 "$D3_URL/v1/systemone" \
  -H 'Content-Type: application/json' --data-binary @/tmp/card-scout-decision.json | jq '.answers'
----

Expect `device: cuda:0` and `dtype: float16`. D3 needs no API key. The image is
Charizard from the English Base Set; compare the returned choices and probabilities.
A model probability is not a calibrated guarantee or a price prediction. The
`rarity_symbol` answer is the model's visual assessment; the prepared service
applies the Base Set mapping only when `card_kind` is `pokemon_tcg`. Other items
have `not_applicable` rarity, without inventing a confidence score.

== Test DeepSeek through MaaS

include::ROOT:partial$run-devspaces.adoc[]

[source,sh,role=execute]
----
# Call the governed language-model endpoint with the client Bearer key and inspect its JSON
# response.
curl --fail-with-body -sS --max-time 180 "${OPENAI_BASE_URL}/chat/completions" \
  -H "Authorization: Bearer $OPENAI_API_KEY" -H 'Content-Type: application/json' \
  -d '{"model":"deepseekv4pro","messages":[{"role":"user","content":"In one sentence, explain why a trading card rarity is different from its market value."}],"max_completion_tokens":256}' | jq '{model,answer:.choices[0].message.content,usage}'
----

Expect an actual answer and measured usage. If you receive a quota error, check the MaaS subscription and Foundry limits.

== Test the native agent and its tool

For this probe, use the injected developer MaaS key with the native Responses
API. The prepared service has a separate runtime key for application research.

include::ROOT:partial$run-devspaces.adoc[]

[source,sh,role=execute]
----
# Prepare the client-key header expected by the native agent; never echo its value.
PROVIDER_DATA=$(jq -cn --arg key "$OPENAI_API_KEY" '{vllm_api_token:$key}')
# Build a native Responses request that requires the named, read-only MCP price tool.
jq -n --arg mcp "$CARD_SCOUT_URL/mcp" '{
  model:"maas-vllm-inference-1/deepseekv4pro",
  input:"Use get_card_market_data once for item-104. Report its exact catalogue identity and Cardmarket EUR trend, 7-day average, update timestamp and source. Do not invent missing prices.",
  tools:[{type:"mcp",server_label:"card_scout_market",server_url:$mcp,require_approval:"never",allowed_tools:["get_card_market_data"]}],
  tool_choice:{type:"mcp",server_label:"card_scout_market",name:"get_card_market_data"},
  max_infer_iters:4,reasoning:{effort:"none"},store:false
}' > /tmp/card-scout-agent.json
# Ask the native OpenShift AI agent to execute the required catalogue tool; jq displays its
# evidence.
curl --fail-with-body -sS --max-time 180   http://lsd-genai-playground-service.card-scout-dev.svc.cluster.local:8321/v1/responses \
  -H "X-OGX-Provider-Data: $PROVIDER_DATA" -H 'Content-Type: application/json' \
  --data-binary @/tmp/card-scout-agent.json | jq '{status,output,usage}'
# Remove the temporary credential-bearing variable from this shell.
unset PROVIDER_DATA
----

Check `status: completed`, an actual `mcp_call` for `item-104`, and dated source
data. A plausible answer without the tool call is not a successful test.
Prices can be missing; do not replace them with a guess.

The generated application will use only the prepared Card Scout API. All three
model/tool paths remain owned by the platform.
