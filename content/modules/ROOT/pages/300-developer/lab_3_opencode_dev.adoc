= Lab 2.3 — Build and Ship Card Scout

Generate a small Go application from `APP_CONTRACT.md`. The platform already owns
the dataset, image classification, native agent, MCP tool, persistence and traces.
The application is an English UI and a same-origin proxy to one prepared API.

[NOTE]
====
*Persona:* Developer +
*Time:* 25–35 minutes +
*Outcome:* An app generated from scratch by DeepSeek in OpenCode, built by Tekton
and delivered through Argo CD.
====

== Step 1: Read the contract

In the *Dev Spaces terminal*:

[source,sh,role=execute]
----
cd "${PROJECT_SOURCE}"
cat APP_CONTRACT.md
oc auth can-i create pipelineruns -n "${APP_NAME}-build"
oc auth can-i create deployments -n "${APP_NAME}-dev"
opencode
----

Expect both permissions to be `yes`. OpenCode reads `AGENTS.md`. Use kbd:[Tab]
to switch between plan and build modes; `/exit` returns to the shell.

== Step 2: Plan

In *plan* mode, paste:

[source,text,role=execute]
----
Build Card Scout from scratch in Go using APP_CONTRACT.md and AGENTS.md. Keep the prepared delivery scaffold and technical app name signal-desk. Use only the prepared CARD_SCOUT_URL API from the Go backend. Plan a simple responsive card grid with Analyze batch, rarity filters, Check price, dated source evidence and MLflow trace links. Do not fetch or copy an existing app, implement model orchestration, add credentials, or change privileges.
----

The plan should contain a small standard-library Go server and embedded UI.
It should not contain a new model client, MCP server, database or price scraper.

== Step 3: Build and deploy

Switch to *build*:

[source,text,role=execute]
----
Implement the plan from scratch and deploy using AGENTS.md. Preserve the scaffold, exact internal registry image, restricted-v2 and HTTPS Route. Test proxy errors, images and fixed-route validation; run go test -race ./..., go vet ./... and a local build. Commit and push all generated application source. Wait for Tekton success, the pushed image, matching Argo CD Git revision and running image digest. Print the app and Argo CD URLs. Never print credentials or fetch reference app code.
----

Keep `image-registry.openshift-image-registry.svc:5000/signal-desk-build/signal-desk:latest`
with `imagePullPolicy: Always`. A local build or an older healthy revision is not
a successful deployment. The app has no model key or Kubernetes token.

== Step 4: Analyze a collection

Open the public HTTPS app Route.

. Click *Analyze batch*. Watch all 51 images progress; completed results remain
  visible and persist when the page reloads.
. Browse the ranking. The collection contains 48 Pokémon cards across eight eras
  and three controls. It is deliberately balanced, not a random booster pack.
. Compare *Rare*, *Needs review* and *Other*. The controls should not offer a
  Pokémon price check. A model can make mistakes; uncertainty stays visible.
. Click *Check price* on a Pokémon card. The native OpenShift AI agent calls the
  prepared MCP tool and verifies the dataset's exact catalogue reference.
. Read the catalogue rarity, Cardmarket EUR trend and 7-day average. Compare
  provider dates and follow *Source*. Missing prices must show *Unavailable*.
. Open *View MLflow trace* and inspect the model and actual tool call.

The grid order comes from D3 predictions, not the held-out catalogue labels or
prices. A rare card is not necessarily valuable. The source data concerns known
catalogue references; this exercise does not authenticate a physical card or
recognize arbitrary uploaded editions.

== Step 5: Ship a small change

Ask OpenCode, in *build* mode:

[source,text,role=execute]
----
Remember the selected card filter in localStorage and restore it on reload. Keep filtering before pagination, the matching count, progress, price evidence and trace links. Add a useful empty state. Test, commit and push, then rebuild and deploy using AGENTS.md. Verify the exact new Git revision and running image digest.
----

Verify the new UI on the Route. In the Dev Spaces terminal:

[source,sh,role=execute]
----
oc annotate application "$APP_NAME" -n "${APP_NAME}-dev" \
  argocd.argoproj.io/refresh=hard --overwrite
oc wait application/"$APP_NAME" -n "${APP_NAME}-dev" \
  --for=jsonpath='{.status.sync.revision}'="$(git rev-parse HEAD)" --timeout=180s
oc get application "$APP_NAME" -n "${APP_NAME}-dev" -o json | \
  jq '{revision:.status.sync.revision,sync:.status.sync.status,health:.status.health.status}'
oc rollout restart deployment/"$APP_NAME" -n "${APP_NAME}-dev"
oc rollout status deployment/"$APP_NAME" -n "${APP_NAME}-dev" --timeout=180s
EXPECTED_DIGEST=$(oc get istag "${APP_NAME}:latest" -n "${APP_NAME}-build" -o jsonpath='{.image.metadata.name}')
oc get pods -n "${APP_NAME}-dev" -l "app.kubernetes.io/name=${APP_NAME}" -o json | \
  jq -e --arg name "$APP_NAME" --arg digest "$EXPECTED_DIGEST" \
  '[.items[].status.containerStatuses[] | select(.name==$name)] | length > 0 and all(.[]; .ready and (.imageID | endswith("@"+$digest)))'
ROUTE=$(oc get route "$APP_NAME" -n "${APP_NAME}-dev" -o jsonpath='{.spec.host}')
curl --fail-with-body -sS "https://${ROUTE}/healthz" | jq .
----

You have generated an app from scratch with DeepSeek, analyzed real images on the T4, checked a price through the native agent and shipped a second revision through the same delivery path.
