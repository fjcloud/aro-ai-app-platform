= Lab 2.2 — Build and Ship Signal Desk

Use DeepSeek in OpenCode to build the game described by `APP_CONTRACT.md`, keeping the prepared delivery scaffold. The reference supplies working API clients and replay rules so the exercise focuses on the app rather than inventing model protocols.

[NOTE]
====
*Persona:* Developer +
*Time:* 35–45 minutes, plus the first archive import +
*Outcome:* English app, generated/adapted with DeepSeek, built by Tekton and deployed by your own Argo CD.
====

== Step 1: Read the contract

In the *Dev Spaces terminal*:

[source,sh,role=execute]
----
cd "${PROJECT_SOURCE}"
cat APP_CONTRACT.md
oc auth can-i create pipelineruns -n "${APP_NAME}-build"
oc auth can-i create deployments -n "${APP_NAME}-dev"
opencode
----

Expect both permissions to be `yes`. Do not give the coding model administrator credentials or ask it to change SCC/RBAC.

== Step 2: Plan

Switch OpenCode to *plan* and paste:

[source,text,role=execute]
----
Build Signal Desk in Go using APP_CONTRACT.md and AGENTS.md. Start from all Go files, go.mod/go.sum and web assets of the linked briefing-desk reference, including tests, native OpenShift AI Responses client, D3 scoring, archived research, MCP and tracing. Keep the prepared scaffold and technical app name live-transcript. The English UI should be one simple page: fund memo, $10,000 paper portfolio and last week's ranked Techmeme news. Explain the model endpoints, archive cutoff, portfolio freezing and actual-price settlement in your plan. No real trades, invented prices or new privileges.
----

Review the plan, especially the distinction between a relevance score and a return. The app must use the platform endpoints from its ConfigMap, not Azure credentials or a model URL guessed by the coding assistant.

== Step 3: Build and deploy

Switch to *build* in the same session:

[source,text,role=execute]
----
Implement the plan and deploy using AGENTS.md. Preserve all existing scaffold files, OAuth, restricted-v2 and the exact internal registry image. Run Go tests and the local build. Commit and push the complete source, wait for Tekton to succeed and verify the image tag before creating Argo CD delivery. Wait for the matching Git revision to be Synced / Healthy and the Deployment rollout. Print the app and Argo CD URLs.
----

The source must be clean and pushed before Tekton starts. `AGENTS.md` supplies the Dockerfile and complete Git → Tekton → Argo CD procedure. A local build or an old healthy revision is not a successful deployment.

[IMPORTANT]
====
Keep `image-registry.openshift-image-registry.svc:5000/live-transcript-build/live-transcript:latest` with `imagePullPolicy: Always`. Do not use `placeholder` or an invented image. The pipeline validates the rendered Deployment before building. Never bypass that check or grant SCCs to fix an error.
====

== Step 4: Play one round

Open the HTTPS app Route and sign in with OpenShift.

. Read the default semiconductor fund memo; expand it if you want to change the fund.
. Click *Load last week's news*. The first run downloads seven days of primary Techmeme stories, then scores them on the single T4. Wait for the ranked count to reach the imported count. Saved snapshots and scores are reused on subsequent loads.
. Click *Export the news* and check the week, collected stories and unavailable archive IDs. A missing item must be disclosed; archived excerpts are not full publisher pages.
. Open an interesting story and click *Find index ideas*. Expect a hypothetical thesis and risk for supported ETF proxies. A high relevance score alone is not a BUY instruction.
. Add a virtual amount to one or more ideas. Stay within $10,000. No return should be revealed yet.
. Click *Reveal this week's result*. The complete portfolio freezes before historical prices are requested. Inspect entry/exit dates and the price-data source.
. If the current week is unfinished, check *Week in progress*. *Update result* may refresh prices without changing choices. *Play again* starts a fresh budget and retains the previous round.

The entry is the first available US session open after the news week; valuation is the last completed US session close this week. Before the first completed session, prices are unavailable and the app must say so. No simulated/random prices or full-week profit claims are acceptable. Returns exclude dividends, fees and slippage.

If a model, archive or price provider is unavailable, the UI must show the error and preserve progress. Do not replace inference with a keyword rule or invented output.

== Step 5: Ship a small change

Ask OpenCode, in *build* mode:

[source,text,role=execute]
----
Add a simple “High relevance only” checkbox above the news list. When selected, show only current memo scores of at least 70/100 and display the filtered count; uncheck to restore all news. Keep the archived corpus export, saved portfolio, scoring, agent tools, OAuth and replay rules unchanged. Test it, commit and push, then rebuild and deploy with AGENTS.md. Wait for the new Git revision and rollout before reporting success.
----

Verify the new UI on the Route. In the Dev Spaces terminal:

[source,sh,role=execute]
----
oc annotate application "$APP_NAME" -n "${APP_NAME}-dev" \
  argocd.argoproj.io/refresh=hard --overwrite
oc wait application/"$APP_NAME" -n "${APP_NAME}-dev" \
  --for=jsonpath='{.status.sync.revision}'="$(git rev-parse HEAD)" --timeout=180s
oc get application "$APP_NAME" -n "${APP_NAME}-dev" -o json | \
  jq '{revision:.status.sync.revision,sync:.status.sync.status,health:.status.health.status}'
oc rollout status deployment/"$APP_NAME" -n "${APP_NAME}-dev" --timeout=180s
ROUTE=$(oc get route "$APP_NAME" -n "${APP_NAME}-dev" -o jsonpath='{.spec.host}')
curl --fail-with-body -sS "https://${ROUTE}/healthz" | jq .
----

You have generated/adapted an app with DeepSeek, played a real-price replay and shipped a second revision through the same delivery path.
