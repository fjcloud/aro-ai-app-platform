= Lab 2.2 — Prompt to Production

You have a Dev Space, DeepSeek-V4 Pro on Foundry, and a short `AGENTS.md`. Three OpenCode sessions take you from an empty tree to a live Fortune Cookie app, then through a real change — still no Ansible, no local Docker.

[NOTE]
====
*Estimated time:* 35 minutes +
*Persona:* Developer +
*What you build:* A Fortune Cookie web application in Go — generated, built with Tekton, deployed via your own Argo CD instance, then updated
====

[TIP]
====
OpenCode reads `AGENTS.md` before every prompt. You do not repeat platform rules — describe what you want. The LLM knows the Dockerfile template and the git, ephemeral Git, and `oc` deploy phases.
====

== Session 2: Build and Deploy

Press kbd:[Tab] to *build* in the *same* session.

[source,text,role=execute]
----
Implement the plan.
----

OpenCode writes the files, compiles, then ships from `AGENTS.md`. When it is done it should print the app route and the Argo CD console URL. The Argo CD `Application` must live in `${APP_NAME}-dev` (never `default`).

=== Checkpoint — the app is live

[source,sh,role=execute]
----
APP_NAME="${APP_NAME:-fortune-cookie}"

APP_ROUTE=$(oc get route $APP_NAME -n ${APP_NAME}-dev \
  -o jsonpath='{.spec.host}' 2>/dev/null)
ARGOCD_ROUTE=$(oc get route argocd-server -n ${APP_NAME}-dev \
  -o jsonpath='{.spec.host}' 2>/dev/null)

echo "================================================"
echo " App:    https://${APP_ROUTE}"
echo " ArgoCD: https://${ARGOCD_ROUTE}"
echo "================================================"

oc get application $APP_NAME -n ${APP_NAME}-dev \
  -o jsonpath='{.status.sync.status} / {.status.health.status}' && echo

curl -sk https://${APP_ROUTE}/healthz
----

Expected:

[source,json]
----
{"status":"ok"}
----

Open both URLs in your browser:

* The app URL shows a random fortune cookie message
* The Argo CD console shows your `fortune-cookie` Application in *Synced / Healthy* — *your* Argo CD instance, scoped to your project

The model wrote the code; the running app serves a slice of strings.

---

== Session 3: Ship a change

Close the GitOps loop: change the app, push, watch Tekton rebuild, roll the deployment. Still no hand-written `kubectl apply` for the app.

Start a new OpenCode session in `${PROJECT_SOURCE}`. Press kbd:[Tab] to *build*:

[source,text,role=execute]
----
Add 10 more fortunes and show the message in a styled card with 🥠. Then ship it.
----

Wait for OpenCode to confirm the PipelineRun succeeded.

You can watch the build in the OpenShift console: *Pipelines → PipelineRuns* in the `fortune-cookie-build` namespace.

[source,sh,role=execute]
----
APP_NAME="${APP_NAME:-fortune-cookie}"

oc get application $APP_NAME -n ${APP_NAME}-dev \
  -o jsonpath='{.status.sync.status} / {.status.health.status}' && echo

oc rollout status deployment/$APP_NAME -n ${APP_NAME}-dev --timeout=120s

ROUTE=$(oc get route $APP_NAME -n ${APP_NAME}-dev -o jsonpath='{.spec.host}')
echo "https://${ROUTE}"
curl -sk https://${ROUTE}/healthz
----

.Expected
[source,text,options=nowrap]
----
Synced / Healthy
----

Open the URL — you should see the cookie emoji 🥠 and the new fortunes.
