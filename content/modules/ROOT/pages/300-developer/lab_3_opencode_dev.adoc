= Lab 2.2 — Prompt to Deployment

You have a Dev Space, DeepSeek-V4 Pro on Foundry, and a short `AGENTS.md`. Three steps in OpenCode take you from an application template to a voice-driven cluster-health app, then through a real change — still no Ansible, no local Docker.

[NOTE]
====
*Estimated time:* 35 minutes +
*Persona:* Developer +
*What you build:* A Cluster Voice web application in Go — generated, built with Tekton, deployed via your own Argo CD instance, then updated
====

[TIP]
====
OpenCode includes `AGENTS.md` in its project context. Describe the application and review the proposed plan. The runbook supplies the Dockerfile and the Git, Tekton and Argo CD steps; the checkpoints verify the result.
====

== Step 3: Build and Deploy

Press kbd:[Tab] to *build* in the *same* session.

[source,text,role=execute]
----
Implement the plan and deploy it using AGENTS.md.
Keep the preconfigured internal-registry image in the Deployment. Wait for Tekton to succeed and the image tag to exist before creating the Argo CD Application. Wait for Synced / Healthy and the Deployment rollout, then print the app and Argo CD URLs.
----

Before Tekton starts, `git status --porcelain` must be empty: the local source you tested must match the pushed commit, including any authorized facilitator-prepared changes.

OpenCode writes the files, compiles, then ships from `AGENTS.md`. When it is done it should print the app route and the Argo CD console URL. The Argo CD `Application` must live in `$\{APP_NAME}-dev` (never `default`).

[IMPORTANT]
====
The template already declares `image-registry.openshift-image-registry.svc:5000/live-transcript-build/live-transcript:latest` with `imagePullPolicy: Always`. Tekton runs `clone → validate-image → build`. A placeholder, wrong build namespace or mismatched rendered image stops the pipeline before Buildah.

For an older personal checkout containing `image: placeholder`, replace it with the reference above and commit/push before rebuilding. Argo CD deploys the manifest from Git; changing only the live Deployment is temporary and can be reverted by GitOps. If an existing app has an image pull error, inspect `oc describe pod` for the exact image and registry error before retrying.
====

=== Checkpoint — the app is live

[source,sh,role=execute]
----
APP_NAME="${APP_NAME:-live-transcript}"

APP_ROUTE=$(oc get route $APP_NAME -n ${APP_NAME}-dev \
  -o jsonpath='{.spec.host}' 2>/dev/null)
ARGOCD_ROUTE=$(oc get route argocd-server -n ${APP_NAME}-dev \
  -o jsonpath='{.spec.host}' 2>/dev/null)

echo "================================================"
echo " App:    https://${APP_ROUTE}"
echo " ArgoCD: https://${ARGOCD_ROUTE}"
echo "================================================"

oc get application $APP_NAME -n ${APP_NAME}-dev \
  -o jsonpath='{.status.sync.status} / {.status.health.status}' && echo

curl -fsS https://${APP_ROUTE}/healthz
----

Expected:

[source,json]
----
{"status":"ok"}
----

Open both URLs in your browser:

* The app URL asks you to sign in with OpenShift. Allow the microphone, ask a question in French, and verify that its text appears. Stop, check the text and click *Ask the cluster*. Expand the monitoring evidence and check that it contains real queries and sample timestamps. The browser microphone indicator must switch off after Stop.
* The Argo CD console shows your `live-transcript` Application in *Synced / Healthy* — *your* Argo CD instance, scoped to your project

For the Argo CD console, sign in as `admin`. Retrieve the password for *your instance* from the workspace terminal:

[source,sh,role=execute]
----
oc get secret argocd-cluster -n ${APP_NAME}-dev \
  -o jsonpath='{.data.admin\.password}' | base64 -d; echo
----

DeepSeek helped write the app. At runtime, the Go backend transcribes with Whisper, then sends the question and selected metrics to DeepSeek through a separate MaaS key. Microphone audio never goes to Foundry. The developer CLI identity and the read-only application identity are separate.

== Step 4: Ship a change

Close the GitOps loop: change the app, push, start a new Tekton build, then restart the Deployment to pull the updated image. In this workshop, builds are started explicitly; a Git push alone does not trigger Tekton.

Start a new OpenCode session in `$\{PROJECT_SOURCE}`. Press kbd:[Tab] to *build*:

[source,text,role=execute]
----
Add a “CPU over 1h” shortcut that fills the question field with “Show CPU utilization over the last hour, with evidence.” Let me submit it explicitly. Keep microphone capture, evidence, authentication and tool validation working. Commit and push, rebuild with Tekton, and deploy using AGENTS.md.
Wait for the matching Git revision in Argo CD to be Synced / Healthy, then print the app URL.
----

Wait for OpenCode to confirm the PipelineRun succeeded.

You can watch the build in the OpenShift console: *Pipelines → PipelineRuns* in the `live-transcript-build` namespace.

Argo CD polls Git. Refresh it and wait for the pushed commit; `Synced / Healthy` can still describe the previous revision immediately after a push.

[source,sh,role=execute]
----
APP_NAME="${APP_NAME:-live-transcript}"

oc annotate application $APP_NAME -n ${APP_NAME}-dev \
  argocd.argoproj.io/refresh=hard --overwrite
oc wait application/$APP_NAME -n ${APP_NAME}-dev \
  --for=jsonpath='{.status.sync.revision}'="$(git rev-parse HEAD)" --timeout=180s

oc get application $APP_NAME -n ${APP_NAME}-dev \
  -o jsonpath='{.status.sync.status} / {.status.health.status}' && echo

oc rollout status deployment/$APP_NAME -n ${APP_NAME}-dev --timeout=120s

ROUTE=$(oc get route $APP_NAME -n ${APP_NAME}-dev -o jsonpath='{.spec.host}')
echo "https://${ROUTE}"
curl -fsS https://${ROUTE}/healthz
----

.Expected
[source,text,options=nowrap]
----
Synced / Healthy
----

Open the URL, click *CPU over 1h*, then *Ask the cluster*. Check that the agent queried `cpu_percent` with the `1h` window and displayed the result evidence. Test the microphone again.
