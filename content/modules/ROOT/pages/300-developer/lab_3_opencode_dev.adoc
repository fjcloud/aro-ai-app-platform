= Lab 2.3 — Build and Ship Card Scout

== Goal

Generate Card Scout from its contract, let OpenCode test and correct its code, then deliver it through Tekton and Argo CD. Ship a second revision to practice the same path again.

Generate a small Go application from `APP_CONTRACT.md`. The platform already owns
the dataset, image classification, native agent, MCP tool, persistence and traces.
The application is an English UI and a same-origin proxy to one prepared API.

[NOTE]
====
*Persona:* Developer +
*Time:* 25–35 minutes +
*Outcome:* An app generated from scratch by DeepSeek in OpenCode, built by Tekton
and delivered through Argo CD.
====

Expect both permissions to be `yes`. OpenCode reads `AGENTS.md`. Use kbd:[Tab]
to switch between plan and build modes; `/exit` returns to the shell.

[IMPORTANT]
====
*Allow roughly 5–15 minutes for generation and test-driven corrections.* A first
draft is not guaranteed to pass; OpenCode should read the fixed test failures and
correct its own app. Delivery then typically needs 3–5 minutes for Tekton and
2–3 minutes for Argo CD. Keep the session open while those waits run. A quota or
permission error is a blocker to report, not a reason to change the model or
weaken tests. Verify the actual final revision, not just the agent’s success claim.
====

== Step 2: Generate, test and ship

Use *build* mode and paste this single prompt:

[source,text,role=execute]
----
Build and deploy the minimal Card Scout app from scratch using APP_CONTRACT.md and AGENTS.md. Keep the prepared tests and scaffold unchanged. Run the provided acceptance tests, fix the app until they pass, ship using DELIVERY.md, and run the live test. Do not read or copy other application source. Finish with the actual test results, app URL, deployed Git revision and image digest.
----

OpenCode runs the fixed acceptance tests and uses their failures to correct the
application. A passing local test is followed by real delivery and the live check.
If access or tooling is unavailable, it must report the blocker instead of
changing permissions or weakening the tests.

Keep `image-registry.openshift-image-registry.svc:5000/card-scout-build/card-scout:latest`
with `imagePullPolicy: Always`. A local build or an older healthy revision is not
a successful deployment. The app has no model key or Kubernetes token.

[NOTE]
====
A fresh analysis of 105 images commonly takes 1–3 minutes. Follow the completed
count in the app. Saved results are reused on reload; a price request can take
longer than a page refresh and the contract permits up to 210 seconds. Preserve
visible errors instead of inventing results or repeatedly restarting the batch.
====

== Step 3: Analyze a collection

Open the public HTTPS app Route.

. Click *Analyze batch*. Watch all 105 images progress; completed results remain
  visible and persist when the page reloads.
. Browse the ranking. The collection is the complete 102-card English Base Set (1999),
  using 1st Edition scans. It includes Pokémon, Trainer and Energy cards,
  not a random booster pack. Three controls bring the batch to 105 images:
  Pikachu artwork, Yu-Gi-Oh! and Magic Black Lotus.
. Check that every card is shown in full, including its borders, edition stamp
  and rarity symbol, on desktop and mobile. Images must retain their portrait
  proportions without cropping.
. The grid follows the API ranking. Non-Pokémon controls must not offer a Pokémon price action. A model can still make mistakes.
. Click *Check price* on a Pokémon card. The native OpenShift AI agent calls the
  prepared MCP tool and verifies the dataset's exact catalogue reference.
. Read the catalogue rarity, Cardmarket EUR trend. Compare
  provider dates and follow *Source*. Missing prices must show *Unavailable*.
. Open *View MLflow trace* and inspect the model and actual tool call.

The grid order comes from D3 predictions, not the held-out catalogue labels or
prices. A rare card is not necessarily valuable. The source data concerns known
catalogue references; this exercise does not authenticate a physical card or
recognize arbitrary uploaded editions.

The template provides acceptance tests before generation. `npm test` checks the
actual Go server and UI against local fixture responses, including errors and retries.
`test:live` checks the delivered app against the real platform. OpenCode must run
both and fix application failures without changing the tests.

== Step 4: Ship a small change

Ask OpenCode, in *build* mode:

[source,text,role=execute]
----
Add the sentence "Rarity is not market value." below the page title. Keep the existing behavior and test hooks. Run npm test, commit and push, then rebuild and deploy using DELIVERY.md. Run the live test and verify the exact new Git revision and running image digest.
----

Verify the new UI on the Route. In the Dev Spaces terminal:

include::ROOT:partial$run-devspaces.adoc[]

[source,sh,role=execute]
----
# Request an Argo CD refresh of the repository state.
oc annotate application "$APP_NAME" -n "${APP_NAME}-dev" \
  argocd.argoproj.io/refresh=hard --overwrite
# Wait for Argo CD to reconcile the exact local Git commit, not an older healthy revision.
oc wait application/"$APP_NAME" -n "${APP_NAME}-dev" \
  --for=jsonpath='{.status.sync.revision}'="$(git rev-parse HEAD)" --timeout=180s
# Inspect Argo CD’s actual revision, synchronization and health.
oc get application "$APP_NAME" -n "${APP_NAME}-dev" -o json | \
  jq '{revision:.status.sync.revision,sync:.status.sync.status,health:.status.health.status}'
# Restart the app pods to load the renewed configuration or newly pushed image.
oc rollout restart deployment/"$APP_NAME" -n "${APP_NAME}-dev"
# Wait for the deployment to become available.
oc rollout status deployment/"$APP_NAME" -n "${APP_NAME}-dev" --timeout=180s
# Read the exact built image digest to compare with the running application.
EXPECTED_DIGEST=$(oc get istag "${APP_NAME}:latest" -n "${APP_NAME}-build" -o jsonpath='{.image.metadata.name}')
# Verify every app container is Ready and uses the expected image digest.
oc get pods -n "${APP_NAME}-dev" -l "app.kubernetes.io/name=${APP_NAME}" -o json | \
  jq -e --arg name "$APP_NAME" --arg digest "$EXPECTED_DIGEST" \
  '[.items[].status.containerStatuses[] | select(.name==$name)] | length > 0 and all(.[]; .ready and (.imageID | endswith("@"+$digest)))'
# Read the generated app’s HTTPS Route hostname.
ROUTE=$(oc get route "$APP_NAME" -n "${APP_NAME}-dev" -o jsonpath='{.spec.host}')
# Verify the deployed app’s health endpoint through its public HTTPS Route.
curl --fail-with-body -sS "https://${ROUTE}/healthz" | jq .
----
