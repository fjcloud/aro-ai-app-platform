= Lab 2.1 — Launch Your Dev Space

Welcome to Act 2. You are now the *Developer*. Everything you need — editor, terminal, and OpenCode pointed at DeepSeek-V4 Pro — is in the browser through *OpenShift Dev Spaces*. No laptop install. The model is the Foundry endpoint from this morning.

[NOTE]
====
*Estimated time:* 10 minutes +
*Persona:* Developer +
*What you need:* The launch URL from Lab 1.5 and your cluster login
====

== What is OpenShift Dev Spaces?

OpenShift Dev Spaces provides *cloud-based developer workspaces* — VS Code-compatible IDEs that run as pods in the cluster. Key benefits:

* *Zero local setup:* the workspace comes pre-configured; just open a browser
* *Consistent environment:* every developer gets the same tools, versions, and configuration
* *Model access:* the workspace calls Foundry at `$OPENAI_BASE_URL` with the injected key — same chat-completions JSON, pay per token
* *Persistent storage:* your work is saved on a per-user PVC even if you close the browser

== Get the Dev Spaces URL

Use the URL you printed in Lab 1.5. It clones the Go app template (`go-app-template`) — not this workshop repo — and creates a workspace from its `devfile.yaml`:

[source,text,options=nowrap]
----
https://devspaces.apps.<cluster>/#https://github.com/fjcloud/go-app-template/tree/aro-transcription?ai-provider=opencodeai/opencode
----

[NOTE]
====
The `#<template-url>` suffix tells Dev Spaces to clone the template and create a workspace from its `devfile.yaml` automatically. OpenCode is injected by the platform. The project `opencode.json` still names the old model until the step below. The workspace comes pre-loaded with `AGENTS.md`, `pipeline/`, `gitops/`, and `deploy/base/` — you only need to write the application code.
====

. Open that URL in your browser.

== Log In and Create Your Workspace

. You will be redirected to OpenShift SSO. Log in with the same cluster user you used for `oc`.

. On the Create Workspace page, confirm that **OpenCode** is selected under *AI Provider*. That selection injects the CLI at start; you do not install it yourself. You will see a progress screen:
+
[source,text]
----
Starting workspace...
Pulling universal developer image...
Injecting OpenCode...
Running postStart commands...
  ✓ Installing the ephemeral Git client
----
+
The first launch can take up to 15 minutes while the images are pulled. *Subsequent launches are faster* — the images are cached.

. When the workspace is ready, a VS Code-like editor opens in the browser. You will see:
** A file explorer on the left
** A terminal at the bottom
** OpenCode available on `PATH` (injected by Dev Spaces, not by the template)
+
Do **not** sign in to GitHub Copilot. Che Code ships Copilot as a built-in; the platform disables it. Do not install Continue. The model is OpenCode in the terminal, calling DeepSeek-V4 Pro.

If the editor opens in *Restricted Mode*, open *Manage Workspace Trust*, trust this repository, and confirm. The IDE may reload before its terminal becomes available.

== Log the workspace terminal into OpenShift

The browser SSO session does not authenticate the `oc` CLI inside a newly created workspace. Its default service account cannot create the namespaces and build permissions used in this lab.

In the OpenShift console, open your user menu → *Copy login command*. Complete login and paste the resulting `oc login` command into the *Dev Spaces terminal*, using the assigned lab administrator from Act 0. Do not paste the token into OpenCode or commit it.

[source,sh,role=execute]
----
oc whoami
oc auth can-i '*' '*' --all-namespaces
----

The permission check must return `yes` before you ask OpenCode to deploy. These are deliberately administrator labs; a production platform would pre-create project permissions and build service accounts for developers. If the answer is `no`, ask the facilitator to prepare the assigned access rather than searching for other credentials.

== Verify OpenCode is Running

. Open a terminal in the workspace (*Terminal → New Terminal* or press kbd:[Ctrl+`]).

. Check that OpenCode is on `PATH` (injected) and that ephemeral Git is configured (`$GIT_SERVER`):
+
[source,sh,role=execute]
----
opencode --version && echo "GIT_SERVER=$GIT_SERVER"
----
+
.Sample Output
[source,text,options=nowrap]
----
1.x.x
GIT_SERVER=https://git.<workshop-domain>
----

. Point the project at the Foundry deployment. The template's `opencode.json` wins over the platform file. Copy the platform configuration and commit it so the personal repository keeps the correct model. This file contains environment references; it contains no key. From the workspace terminal:
+
[source,sh,role=execute]
----
cd "${PROJECT_SOURCE}"
cp "${XDG_CONFIG_HOME:-$HOME/.config}/opencode/opencode.json" opencode.json
git add opencode.json
git -c user.name="Workshop Developer" -c user.email="dev@workshop.local" \
  commit -m "Use the workshop Foundry model"
----
+
. Ask DeepSeek for one sentence. `$OPENAI_BASE_URL` already ends in `/openai/v1`.
+
[source,sh,role=execute]
----
curl --fail-with-body -sS --max-time 180 "${OPENAI_BASE_URL}/chat/completions" \
  -H "Content-Type: application/json" \
  -H "api-key: $OPENAI_API_KEY" \
  -d '{"model":"deepseekv4pro","messages":[{"role":"user","content":"Reply with one short sentence."}],"max_completion_tokens":256}'
----
+
[TIP]
====
`$OPENAI_API_KEY` and `$OPENAI_BASE_URL` come from Secret `ai-provider-openai-api-key`. The model id is the deployment name `deepseekv4pro`. A short reply costs a fraction of a cent. Reasoning tokens, when the response includes them, are billed as output.
====

. Start OpenCode:
+
[source,sh,role=execute]
----
opencode
----
+
The OpenCode TUI (Terminal UI) launches. It reads `AGENTS.md` and connects to DeepSeek-V4 Pro automatically.
Two session modes are available: *plan* (read-only — no file writes) and *build* (writes files). Press kbd:[Tab] to switch from one to the other.
Use `/exit` to leave OpenCode when needed.

== Understanding the OpenCode Configuration

OpenCode reads **project** `opencode.json` first (it overrides the platform mount under `~/.config/opencode`). Verify the file in the template:

[source,sh,role=execute]
----
cat ${PROJECT_SOURCE}/opencode.json
----

Expected content:

[source,json]
----
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "deepseek": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "DeepSeek-V4 Pro",
      "options": {
        "baseURL": "{env:OPENAI_BASE_URL}",
        "apiKey": "{env:OPENAI_API_KEY}",
        "headers": {
          "api-key": "{env:OPENAI_API_KEY}"
        },
        "chunkTimeout": 120000,
        "timeout": 600000
      },
      "models": {
        "deepseekv4pro": {
          "name": "DeepSeek-V4 Pro",
          "limit": {
            "context": 131072,
            "output": 32768
          }
        }
      }
    }
  },
  "model": "deepseek/deepseekv4pro",
  "autoupdate": false
}
----

OpenCode still reads `AGENTS.md` from the project directory at the start of every session. That is how the Platform Engineer's rules are enforced.

`limit.output` is 32 768. Input is $1.74 per million tokens and output is $3.48 per million, so keep prompts specific.
