= Lab 2.1 — Launch Your Dev Space

include::ROOT:partial$pr-preview.adoc[]

== Goal

Open a browser workspace with the app template, CLI tools and OpenCode configured for DeepSeek. Sign in as `dev` to use the platform prepared in Act 1.

[NOTE]
====
*Estimated time:* 10 minutes +
*Persona:* Developer +
*What you need:* The platform prepared in Act 1 and your cluster login
====

== Get the Dev Spaces URL

The models and runtime agent backend are now ready. In the *cluster terminal*, generate the workspace launch link:

include::ROOT:partial$run-cluster.adoc[]

[source,sh,role=execute]
----
# Read the operator-reported browser IDE URL for this cluster.
DEVSPACES_URL=$(oc get checluster devspaces -n openshift-operators -o jsonpath='{.status.cheURL}')
# Wait for all CPU-node image caches before launching the workspace.
oc rollout status daemonset/kubernetes-image-puller -n openshift-operators --timeout=600s
# Select the ARO template branch; it contains scaffolding and tests, not a finished app.
TEMPLATE_URL=https://github.com/fjcloud/go-app-template/tree/aro-card-scout
# Print the prepared browser launch URL; no credential is included.
printf '%s/#%s?ai-provider=opencodeai/opencode\n' "${DEVSPACES_URL%/}" "$TEMPLATE_URL"
----

Open the printed link in a *private window or separate browser profile*.
This keeps the developer's login separate from your administrator session.
The link selects the template and OpenCode; Dev Spaces creates a workspace in
the prepared *dev-devspaces* project.

== Log In and Create Your Workspace

. You will be redirected to OpenShift SSO. Choose *workshop* and log in as `dev`.

. On first access, click *Log in with OpenShift* if prompted, then *Allow selected permissions* for the Dev Spaces client. The redirect should return to your lab's Dev Spaces address.

. If Dev Spaces asks whether you trust the repository, confirm *Continue* for `fjcloud/go-app-template`. This starts workspace creation.

If the factory reports *Devfile hasn't been resolved in the last 20 seconds*, use *Click to try again*. Keep the repository's devfile; do not choose *Continue with default devfile*.

. The launch URL selects **OpenCode** automatically. If a Create Workspace form appears, confirm **OpenCode** under *AI Provider*. This injects the CLI at start; you do not install it yourself. You will see a progress screen:
+
[source,text]
----
Starting workspace...
Pulling universal developer image...
Injecting OpenCode...
Running postStart commands...
  ✓ Installing the ephemeral Git client
----
+
[IMPORTANT]
====
*Allow 2–5 minutes with cached images; the first start can take up to 15 minutes.*
Storage and the persistent home still need initialization. The cache wait above
permits 10 minutes before launch. Keep the start screen open; do not create extra
workspaces while one is starting. A timeout or an error in *Events* is a failure
to inspect, not proof that the IDE is ready.
====

. When the workspace is ready, a VS Code-like editor opens in the browser. You will see:
** A file explorer on the left
** A terminal at the bottom
** OpenCode available on `PATH` (injected by Dev Spaces, not by the template)
+
Use OpenCode in the terminal to call DeepSeek-V4 Pro.

If the editor opens in *Restricted Mode*, click *Manage* in the banner, then
*Trust*. The IDE may reload before its terminal becomes available.

== Open the terminal inside Dev Spaces

In the browser editor’s top menu, choose *Terminal → New Terminal*. A shell opens
in the bottom panel. If the menu is collapsed, use the editor’s main menu or
kbd:[Ctrl+Shift+P], then run *Terminal: Create New Terminal*. This is the Dev Spaces
terminal. Use it for all Act 2 commands.

Run developer commands here, in `$PROJECT_SOURCE`. Shell blocks go into this
terminal; natural-language prompt blocks go into OpenCode after it starts.

== Check your scoped CLI access

The platform injects a separate developer kubeconfig into the workspace. Browser SSO and CLI access are separate; you do not paste an administrator token into the terminal or OpenCode.

include::ROOT:partial$run-devspaces.adoc[]

[source,sh,role=execute]
----
# Show the CLI identity actually used by this terminal.
oc whoami
# Expect yes: the scoped identity can start application builds.
oc auth can-i create pipelineruns -n "${APP_NAME}-build"
# Expect yes: this identity can deploy in the application project.
oc auth can-i create deployments -n "${APP_NAME}-dev"
----

Expect `system:serviceaccount:card-scout-dev:workshop-developer`, then `yes`
and `yes`. If access is missing, ask the platform engineer to repeat the
preparation in Lab 1.7 and restart the workspace.

The template also includes a local-only browser component for acceptance tests.
OpenCode prepares it with `npm ci && npm run setup`. No system-package installation
is needed in the developer container. The generated app remains a Go application.

== Verify OpenCode is Running

. Open a terminal in the workspace (*Terminal → New Terminal* or press kbd:[Ctrl+`]).

. Check that OpenCode is on `PATH` (injected) and that ephemeral Git is configured (`$GIT_SERVER`):
+
include::ROOT:partial$run-devspaces.adoc[]

[source,sh,role=execute]
----
# Verify that OpenCode and the platform Git client are available in this workspace.
opencode --version && command -v gitpop && echo "GIT_SERVER=$GIT_SERVER"
----
+
.Sample Output
[source,text,options=nowrap]
----
1.x.x
/home/user/.local/bin/gitpop
GIT_SERVER=https://git.<workshop-domain>
----

. Check the project model configuration against the platform. The template's `opencode.json` wins over the platform file; both should pin DeepSeek through MaaS. This file contains environment references; it contains no key. From the workspace terminal:
+
include::ROOT:partial$run-devspaces.adoc[]

[source,sh,role=execute]
----
# Use the cloned project directory inside Dev Spaces.
cd "${PROJECT_SOURCE}"
# Align the project’s model configuration with the injected platform configuration; it
# contains environment references, not a key.
cp "${XDG_CONFIG_HOME:-$HOME/.config}/opencode/opencode.json" opencode.json
# Commit only when the injected configuration differs from the template.
if ! git diff --quiet HEAD -- opencode.json; then
  # Stage only the intended model-configuration update.
  git add opencode.json
  # Commit the configuration change using the workshop developer identity.
  git -c user.name="Workshop Developer" -c user.email="dev@workshop.local" \
    commit -m "Use DeepSeek through the workshop MaaS gateway"
fi
----
+
. Test both model APIs in *Lab 2.2* before starting OpenCode. Your MaaS key is already injected; do not print it.

== Check the workspace identity in the UI

Open the Dev Spaces dashboard in the same developer browser session. Confirm
that the user menu shows *dev* and that the workspace belongs to *dev-devspaces*.
In the editor, `oc whoami` should show
`system:serviceaccount:card-scout-dev:workshop-developer`. These different names
are expected: the browser creates the workspace as the person; the CLI uses a
limited service account so OpenCode cannot administer the cluster.

== Model configuration

OpenCode uses the project `opencode.json`. Inspect it to confirm the model is
`deepseek/deepseekv4pro` and the URL and key are environment references:

include::ROOT:partial$run-devspaces.adoc[]

[source,sh,role=execute]
----
# Inspect the model configuration without printing the injected key.
jq . "${PROJECT_SOURCE}/opencode.json"
----
