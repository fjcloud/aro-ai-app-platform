= Lab 2.1 — Launch Your Dev Space

Welcome to Act 2. You are now the *Developer*. Everything you need — editor, terminal, and OpenCode pointed at DeepSeek-V4 Pro — is in the browser through *OpenShift Dev Spaces*. No laptop installation is required. The model is published through the OpenShift AI MaaS gateway from this morning.

[NOTE]
====
*Estimated time:* 10 minutes +
*Persona:* Developer +
*What you need:* The launch URL from Lab 1.5 and your cluster login
====

== What is OpenShift Dev Spaces?

OpenShift Dev Spaces provides *cloud-based developer workspaces* — VS Code-compatible IDEs that run as pods in the cluster. Key benefits:

* *Zero local setup:* the workspace comes pre-configured; just open a browser
* *Consistent environment:* every developer gets the same tools, versions, and configuration
* *Model access:* the workspace calls MaaS at `$OPENAI_BASE_URL` with an injected MaaS key — same chat-completions JSON, pay per token
* *Persistent storage:* your work survives closing the browser, but remains tied to the lifetime of this RHDP environment. Export anything you want to keep before it expires

== Get the Dev Spaces URL

Use the URL you printed in Lab 1.5. It clones the Go app template (`go-app-template`) — not this workshop repo — and creates a workspace from its `devfile.yaml`:

[source,text,options=nowrap]
----
https://devspaces.apps.<cluster>/#https://github.com/fjcloud/go-app-template/tree/aro-transcription?ai-provider=opencodeai/opencode
----

[NOTE]
====
The `#<template-url>` suffix tells Dev Spaces to clone the template and create a workspace from its `devfile.yaml` automatically. OpenCode is injected by the platform. The project `opencode.json` already pins DeepSeek through MaaS. The workspace comes pre-loaded with `AGENTS.md`, `pipeline/`, `gitops/`, and `deploy/base/` — you only need to write the application code.
====

. Open that URL in your browser.

== Get the OpenShift password from the bastion

The RHDP catalog password opens your assigned environment; it is not the OpenShift password. Use the ARO administrator credentials in the assignment’s access details. If you need to retrieve the password, run this in the *bastion terminal*, where Azure CLI is already authenticated:

[source,sh,role=execute]
----
cd "$HOME/aro-ai-app-platform"
source state/workshop.env
az aro list-credentials --name "${ARO_CLUSTER_ID##*/}" \
  --resource-group "$RESOURCEGROUP" --subscription "$SUBSCRIPTION" \
  --query kubeadminPassword -o tsv
----

This displays the password for the `kubeadmin` browser login. Keep it out of OpenCode and Git. The Azure credentials used by this command remain on the bastion.

[TIP]
====
A facilitator can configure a named https://docs.redhat.com/en/documentation/openshift_container_platform/4.21/html-single/authentication_and_authorization/authentication_and_authorization[HTPasswd user] for the console and Dev Spaces. Authentication does not grant deployment permissions: this workshop currently needs a lab administrator to create namespaces and grant the pipeline’s build SCC. A restricted developer flow requires the facilitator to pre-create the app namespaces, build service accounts and scoped permissions, and adapt the deployment runbook accordingly.
====

== Log In and Create Your Workspace

. You will be redirected to OpenShift SSO. Log in as `kubeadmin` with the ARO password, or use the named workshop user prepared by your facilitator. An administrative certificate login shown as `system:admin` by the bastion’s `oc whoami` is not a browser username.

. On the Create Workspace page, confirm that **OpenCode** is selected under *AI Provider*. That selection injects the CLI at start; you do not install it yourself. You will see a progress screen:
+
[source,text]
----
Starting workspace...
Pulling universal developer image...
Injecting OpenCode...
Running postStart commands...
  ✓ Installing the ephemeral Git client
----
+
The first launch can take up to 15 minutes while the images are pulled. *Subsequent launches are faster* — the images are cached.

. When the workspace is ready, a VS Code-like editor opens in the browser. You will see:
** A file explorer on the left
** A terminal at the bottom
** OpenCode available on `PATH` (injected by Dev Spaces, not by the template)
+
Do **not** sign in to GitHub Copilot. Che Code ships Copilot as a built-in; the platform disables it. Do not install Continue. Use OpenCode in the terminal to call DeepSeek-V4 Pro.

If the editor opens in *Restricted Mode*, open *Manage Workspace Trust*, trust this repository, and confirm. The IDE may reload before its terminal becomes available.

== Log the workspace terminal into OpenShift

The browser SSO session does not authenticate the `oc` CLI inside a newly created workspace. Its default service account cannot create the namespaces and build permissions used in this lab.

In the OpenShift console, open your user menu → *Copy login command*. Complete login and paste the resulting `oc login` command into the *Dev Spaces terminal*, using the assigned lab administrator from Act 0. Do not paste the token into OpenCode or commit it.

[source,sh,role=execute]
----
oc whoami
oc auth can-i '*' '*' --all-namespaces
----

The permission check must return `yes` before you ask OpenCode to deploy. These are deliberately administrator labs; a production platform would pre-create project permissions and build service accounts for developers. If the answer is `no`, ask the facilitator to prepare the assigned access rather than searching for other credentials.

== Verify OpenCode is Running

. Open a terminal in the workspace (*Terminal → New Terminal* or press kbd:[Ctrl+`]).

. Check that OpenCode is on `PATH` (injected) and that ephemeral Git is configured (`$GIT_SERVER`):
+
[source,sh,role=execute]
----
opencode --version && echo "GIT_SERVER=$GIT_SERVER"
----
+
.Sample Output
[source,text,options=nowrap]
----
1.x.x
GIT_SERVER=https://git.<workshop-domain>
----

. Check the project model configuration against the platform. The template's `opencode.json` wins over the platform file; both should pin DeepSeek through MaaS. The following also updates older workspaces when needed. This file contains environment references; it contains no key. From the workspace terminal:
+
[source,sh,role=execute]
----
cd "${PROJECT_SOURCE}"
cp "${XDG_CONFIG_HOME:-$HOME/.config}/opencode/opencode.json" opencode.json
if ! git diff --quiet HEAD -- opencode.json; then
  git add opencode.json
  git -c user.name="Workshop Developer" -c user.email="dev@workshop.local" \
    commit -m "Use DeepSeek through the workshop MaaS gateway"
fi
----
+
. Ask DeepSeek for one sentence. `$OPENAI_BASE_URL` already ends in `/v1`.
+
[source,sh,role=execute]
----
curl --fail-with-body -sS --max-time 180 "${OPENAI_BASE_URL}/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -d '{"model":"deepseekv4pro","messages":[{"role":"user","content":"Reply with one short sentence."}],"max_completion_tokens":256}'
----
+
[TIP]
====
`$OPENAI_API_KEY` and `$OPENAI_BASE_URL` come from Secret `ai-provider-openai-api-key`. This is a MaaS key, not the Azure account key. The client model id is `deepseekv4pro`. A short reply costs a fraction of a cent. Reasoning tokens, when the response includes them, are billed as output.
====

. Start OpenCode:
+
[source,sh,role=execute]
----
opencode
----
+
The OpenCode terminal user interface (TUI) launches. It reads `AGENTS.md` and connects to DeepSeek-V4 Pro automatically.
Two session modes are available: *plan* (read-only — no file writes) and *build* (writes files). Press kbd:[Tab] to switch from one to the other.
Use `/exit` to leave OpenCode when needed.

== Understanding the OpenCode Configuration

OpenCode reads **project** `opencode.json` first (it overrides the platform mount under `~/.config/opencode`). Verify the file in the template:

[source,sh,role=execute]
----
cat ${PROJECT_SOURCE}/opencode.json
----

Expected content:

[source,json]
----
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "deepseek": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "DeepSeek-V4 Pro",
      "options": {
        "baseURL": "{env:OPENAI_BASE_URL}",
        "apiKey": "{env:OPENAI_API_KEY}",
        "chunkTimeout": 120000,
        "timeout": 600000
      },
      "models": {
        "deepseekv4pro": {
          "name": "DeepSeek-V4 Pro",
          "limit": {
            "context": 131072,
            "output": 32768
          }
        }
      }
    }
  },
  "model": "deepseek/deepseekv4pro",
  "autoupdate": false
}
----

OpenCode still reads `AGENTS.md` from the project directory at the start of every session. These instructions guide generation. Tekton validates the image reference, and you check the deployed application in Lab 2.2.

`limit.output` is 32 768. Keep prompts specific and review usage and pricing in Lab 3.1.
