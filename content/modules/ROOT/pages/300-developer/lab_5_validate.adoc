== Why this matters

`AGENTS.md` supplies instructions to the model. It is not a policy enforcement mechanism, and a model can miss a rule. Keep CI checks, OpenShift admission controls and human review as independent safeguards. This lab combines an agent-assisted review with direct checks of cluster resources.

The template protects `deploy/`, `pipeline/` and `gitops/` from agent rewrites. Ask OpenCode to report differences first. If a correction to the scaffold is needed, the platform owner reviews and applies it, then you rebuild and deploy using the same delivery steps as Lab 2.2.

== Audit 3: Security & TLS

[source,text,role=execute]
----
Review pod and container security and Route TLS in deploy/base/ against AGENTS.md. Report differences without editing files, including non-root execution, dropped capabilities and HTTPS redirect.
----

Inspect the security context declared in the Deployment:

[source,sh,role=execute]
----
APP_NAME="${APP_NAME:-live-transcript}"
oc get deployment "$APP_NAME" -n "${APP_NAME}-dev" \
  -o jsonpath='{.spec.template.spec.securityContext}' | python3 -m json.tool
----

.Expected
[source,json,options=nowrap]
----
{
  "runAsNonRoot": true,
  "seccompProfile": { "type": "RuntimeDefault" }
}
----

The Deployment leaves `runAsUser` unset so OpenShift can assign a UID from the namespace range. The admitted Pod can contain fields added by the SCC; its JSON need not match this excerpt exactly. Also verify the container drops `ALL` capabilities and sets `allowPrivilegeEscalation: false`.

Check container security and the SCC selected for the running Pod:

[source,sh,role=execute]
----
oc get deployment "$APP_NAME" -n "${APP_NAME}-dev" \
  -o jsonpath='{.spec.template.spec.containers[0].securityContext}' | python3 -m json.tool
oc get pods -n "${APP_NAME}-dev" -l app.kubernetes.io/name="$APP_NAME" \
  -o 'custom-columns=NAME:.metadata.name,SCC:.metadata.annotations.openshift\.io/scc'
----

Expect `allowPrivilegeEscalation: false`, `capabilities.drop: ["ALL"]`, and the `restricted-v2` SCC. This application’s SCC is distinct from the privileged SCC used by the Tekton build service account.

Verify Route TLS:

[source,sh,role=execute]
----
APP_NAME="${APP_NAME:-live-transcript}"
oc get route $APP_NAME -n ${APP_NAME}-dev \
  -o jsonpath='{.spec.tls.termination} / {.spec.tls.insecureEdgeTerminationPolicy}'
----

.Expected
[source,text,options=nowrap]
----
edge / Redirect
----

== Final State Check

[source,sh,role=execute]
----
APP_NAME="${APP_NAME:-live-transcript}"

echo "=== Resource Limits ==="
oc get deployment $APP_NAME -n ${APP_NAME}-dev \
  -o jsonpath='{.spec.template.spec.containers[0].resources}' | python3 -m json.tool

echo ""
echo "=== Health Probes ==="
oc get deployment $APP_NAME -n ${APP_NAME}-dev \
  -o jsonpath='{.spec.template.spec.containers[0].livenessProbe.httpGet}' | python3 -m json.tool

echo ""
echo "=== Pod Security Context ==="
oc get deployment $APP_NAME -n ${APP_NAME}-dev \
  -o jsonpath='{.spec.template.spec.securityContext}' | python3 -m json.tool

echo ""
echo "=== Route TLS ==="
oc get route $APP_NAME -n ${APP_NAME}-dev \
  -o jsonpath='{.spec.tls.termination} / {.spec.tls.insecureEdgeTerminationPolicy}' && echo
----
