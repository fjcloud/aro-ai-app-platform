= AI-Powered Developer Platform on ARO

Build *Card Scout*: analyze a mixed-era trading-card collection, rank likely rare cards and ask a native OpenShift AI agent to verify a selected card and retrieve dated market prices.

You play two roles. The *platform engineer* prepares OpenShift AI, a managed DeepSeek endpoint, one local T4 decision model and the delivery tools. The *developer* uses OpenCode and a short app contract to generate and ship a small Go UI from scratch. Finally, inspect model usage, agent tools and MLflow traces.

== The workshop in five steps

. *Platform:* apply all operator manifests with `oc`.
. *Infrastructure:* add one CPU worker and one single-T4 worker, then enable platform instances.
. *Models:* deploy DeepSeek on Foundry, publish it through OpenShift AI MaaS, and serve d3-mini on the T4.
. *Developer preflight:* from Dev Spaces, explain and test each API independently with `curl | jq`, using the MaaS key for DeepSeek.
. *Application:* generate from `APP_CONTRACT.md`, analyze the prepared images, browse rarity predictions and check a price through the native agent.

== What you build

[source,text]
----
Dev Spaces / OpenCode → OpenShift AI MaaS → DeepSeek on Foundry (coding)

Fixed mixed-era images → Card Scout platform → d3-mini on T4 → rarity ranking
Browser → generated Go UI/proxy → native OpenShift AI agent → DeepSeek / MaaS
                                                ↕ read-only MCP → TCGdex prices
Playground → same MCP tool                 Model and tool spans → MLflow
Git → Tekton → Argo CD → same Go app
----

*DeepSeek* generates the application and powers its price agent, using separate
MaaS keys. *d3-mini* classifies images without generating prose. OpenShift AI/KServe
serves it on one T4. The prepared service owns models, tools, persistence and
tracing; the generated application calls one API and needs no model credential.

The dataset spans eight eras, from 1999 to 2023. Its catalogue references are
known; model predictions and verified catalogue rarity remain distinct. Rarity
is not market value. Prices retain their currency, source and update timestamp.

== Workshop structure

[cols="1,2,3",options="header"]
|===
| Act | Role | Labs
| 0 — Get in | Platform Engineer | Connect to the assigned RHDP ARO environment and detect its resource group.
| 1 — Build the platform | Platform Engineer | Apply all operator manifests; add one D8 CPU worker and one single-T4 worker; enable platform instances; deploy DeepSeek and publish it through MaaS; serve d3-mini and prepare scoped developer access, the runtime agent and tracing.
| 2 — First day | Developer | Open Dev Spaces; learn the decision-model contract and test both models independently with curl + jq; generate Card Scout from APP_CONTRACT.md; ship through Tekton and Argo CD; analyze images and verify a card price.
| 3 — Observe and evaluate | Both | Compare coding, agent and GPU usage; inspect traces and exercise the same bounded tools in the Playground.
|===

Allow roughly half a day including operator installation, GPU provisioning and downloads. Operator installation and worker creation use explicit `oc` / `az` commands and supplied manifests. Run Acts 0 and 1 in the *bastion terminal*. Act 2 runs in the *Dev Spaces terminal*. Paste shell blocks into the named terminal and prompt blocks into OpenCode; use `/exit` to return to the shell. JSON responses are formatted with `jq`.

== Prerequisites

* Assigned RHDP *classic ARO* environment, OpenShift 4.21+, Ready workers and WeTTY browser terminal.
* Cluster-admin access for the platform role; a separate scoped developer identity is prepared for Act 2.
* Azure permissions for Foundry in the assigned resource group, plus quota and capacity for one `Standard_NC8as_T4_v3` worker and CPU headroom.
* A browser; no laptop model, Docker, API key or GitHub account is required from participants.

Use one assigned cluster per participant. A shared cluster requires the facilitator to isolate app names, namespaces and permissions before the workshop.
