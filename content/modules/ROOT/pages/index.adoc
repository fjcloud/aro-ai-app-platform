= AI-Powered Developer Platform on ARO

Welcome to the *AI-Powered Developer Platform on ARO* workshop.

The story for today is a Monday at a company that uses a managed coding model and keeps speech inference on its own cluster. This morning the platform team publishes DeepSeek-V4 Pro as a managed Foundry endpoint. The platform also serves Whisper on one T4 with OpenShift AI. This afternoon a developer ships a browser transcription app from OpenShift Dev Spaces. You wear both hats, then you review token usage, infrastructure costs and cleanup.

== What You Will Build

image::architecture-overview.png[Separate coding and speech model paths on ARO, align="center"]

DeepSeek writes the app; Whisper transcribes its audio. Coding prompts and source context leave the cluster for Foundry. Browser audio goes through the Go backend to the internal Whisper service.

=== Act 1 — Platform
* *DeepSeek-V4 Pro* on Microsoft Foundry, Global Standard, pay per token
* *OpenShift Dev Spaces* pointed at that endpoint with one injected key
* *OpenShift AI + KServe + Red Hat AI Inference* serving RedHatAI Whisper Large v3 Turbo INT8 on one NVIDIA T4
* *AGENTS.md* — project instructions for OpenCode
* *OpenShift GitOps* (Argo CD) and *OpenShift Pipelines* (Tekton)

=== Act 2 — Developer
* A personal Git repository on *ephemeral Git* (workshop-scoped, no GitHub account)
* A *Live Transcript* Go app with browser microphone capture, generated live by OpenCode + DeepSeek-V4 Pro
* Image build and GitOps deploy from git, ephemeral Git, and `oc` — no Ansible, no local Docker
* Platform rules (limits, probes, SCC, TLS) audited by the same model

=== Act 3 — The bill
* Input and output tokens from the afternoon, priced from the Foundry list rate
* GPU, CPU and storage costs while provisioned, plus scoped facilitator cleanup

== Learning Outcomes

After completing this workshop, you will understand:

* How a Foundry Global Standard deployment publishes an OpenAI-compatible model for coding, alongside a separate T4 speech model
* How `AGENTS.md` gives the coding agent platform conventions, backed by deployment checks
* How Dev Spaces + OpenCode is an AI-augmented inner loop with no laptop install
* How Tekton and Argo CD form a GitOps path from a single repository
* How managed coding tokens and provisioned speech infrastructure have different cost models

== How to follow the labs

The morning/afternoon story represents two roles; you play both. Allow roughly half a day, including provisioning and image downloads. Timings are estimates.

Run Acts 0 and 1 in the *bastion terminal* from Cloud Terminal. In Act 2, switch to the *Dev Spaces terminal* in the browser IDE. Lab 3.1 names the terminal to use for each task. Paste shell blocks into a terminal and prompt blocks into OpenCode. Use `/exit` to leave OpenCode, or open another terminal for checkpoint commands.

The platform uses cluster-wide resources and the app uses fixed namespace names. Use one assigned cluster per participant. If several people share a cluster, the facilitator runs Act 1 once and assigns isolated app names, manifests and permissions before Act 2.

== Prerequisites

You will need:

* A current web browser and a microphone
* An assigned RHDP *classic ARO* environment with OpenShift 4.21 or later, a bastion and WeTTY terminal
* Azure permissions, quota and capacity for one `Standard_NC8as_T4_v3` GPU worker and additional CPU headroom when needed
* Cluster-admin access and an Azure identity allowed to create Foundry resources in the assigned resource group
* This workshop repository (cloned in Act 0) — not the Go app template
