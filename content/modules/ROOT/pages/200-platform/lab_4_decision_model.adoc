== Goal

Serve a focused image-decision model on the local T4. Unlike DeepSeek, D3 selects among supplied choices and returns probabilities: here it identifies Pokémon cards and their printed rarity symbols.

[NOTE]
====
*Persona:* Platform Engineer +
*Time:* 5 minutes active; allow time for the first model download. +
*Requires:* Classic ARO 4.21+, cluster-admin, Azure permissions, CPU headroom and T4 capacity.
====

d3-mini is a 4.54B-parameter community decision model from https://huggingface.co/vllm-sr/d3-mini[vLLM Semantic Router], Apache-2.0 licensed. It returns choices or ordinal scores without generating a paragraph. OpenShift AI/KServe manages its native runtime. DeepSeek remains the managed language model.

The published runtime is built from the *Red Hat AI Inference Server* image `registry.redhat.io/rhaii/vllm-cuda-rhel9:3.5.0`, pinned by digest in `deploy/decision/runtime/Dockerfile`. It adds the pinned vLLM Semantic Router decision engine. The resulting image is built before the workshop and pinned by digest in `servingruntime.yaml`.

FP16 fits on a single 16 GB T4. Do not run another GPU model on the same card for this exercise.

== Check GPU discovery and the driver

The operators were installed in Lab 1.1 and their instances enabled in Lab 1.3. The NVIDIA operator now configures the new T4 node.

Inspect GPU discovery and the driver:

include::ROOT:partial$run-cluster.adoc[]

[source,sh,role=execute]
----
# Inspect whether the NVIDIA operator has completed driver/device setup.
oc get clusterpolicy gpu-cluster-policy
# Inspect the worker/GPU labels and reported allocatable resources.
oc get nodes -l workshop.fjcloud.io/gpu=t4 \
  -o 'custom-columns=NAME:.metadata.name,GPU:.status.allocatable.nvidia\.com/gpu'
----

Continue when `GPU` is `1`. A Ready node alone does not prove that its GPU driver is ready.

[IMPORTANT]
====
*GPU driver setup can take 5–15 minutes on a fresh node.* The previous lab waits
for one allocatable GPU. If that check failed, inspect the NVIDIA operator and
node events first; creating a model pod cannot repair an unavailable GPU.
====

== Deploy d3-mini

OpenShift AI/KServe manages two resources: `ServingRuntime/d3-native` defines the image and startup arguments; `InferenceService/d3-mini` selects that runtime and requests one T4. A PVC keeps the downloaded model weights.

Update the workshop checkout before applying the model manifests, then inspect and deploy them with the CLI:

include::ROOT:partial$run-cluster.adoc[]

[source,sh,role=execute]
----
# Update this checkout only if it can fast-forward; do not overwrite local changes.
git pull --ff-only
# Inspect the model runtime image and startup configuration.
cat deploy/decision/servingruntime.yaml
# Inspect the inference service’s resource requests and storage.
cat deploy/decision/inferenceservice.yaml
# Create the private D3 inference service, runtime and model-cache PVC.
oc apply -k deploy/decision
# Wait for the model runtime to load its weights and serve requests.
oc wait inferenceservice/d3-mini -n decision-serving --for=condition=Ready --timeout=1800s
# Check the created resources and their status.
oc get inferenceservice,servingruntime,pvc -n decision-serving
# Inspect the model pods and their readiness.
oc get pods -n decision-serving
----

[IMPORTANT]
====
*The first model start commonly takes 5–15 minutes; the wait permits 30 minutes.*
The runtime image is large and model weights must be downloaded once. During
this time `ContainerCreating` or model loading is expected. `ImagePullBackOff`,
`FailedScheduling` or a readiness timeout requires investigation; it is not a
reason to add another GPU or continue to the developer labs.
====

OpenShift AI starts the published runtime on the T4. On its first start, it downloads the pinned model into the persistent cache. Later starts reuse those weights. No image build, Git credentials or Tekton runtime pipeline is needed in this lab.

Expect a Ready `d3-mini` inference service and no public model Route. The decision endpoint is fixed:

[source,text]
----
http://d3-mini.decision-serving.svc.cluster.local:8080/v1/systemone
----

== Make the model available to developers

Developers and the prepared Card Scout service call the same internal model directly. d3-mini requires no API key or authentication proxy in this workshop. Its NetworkPolicy allows the Card Scout platform service, Dev Spaces and monitoring namespaces; no public Route is created.

The developer tests this endpoint in Lab 2.2 before coding.

== Check in OpenShift AI

Use the OpenShift AI URL from Lab 1.3, signed in as `workshop-admin`.
In *AI hub → Models*, select project *decision-serving* and inspect *d3-mini*.
Check its deployment status and the requested single GPU. In the OpenShift console,
*Workloads → Pods → decision-serving* shows the runtime pod and its events.

The web UI helps you inspect the CLI-created service; do not deploy another
copy from the UI. The two successful outcomes are a Ready inference service and
an internal endpoint. The absence of a public Route is intentional.
