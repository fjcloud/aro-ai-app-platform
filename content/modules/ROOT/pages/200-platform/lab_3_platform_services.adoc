= Lab 1.3 — Enable Platform Services

include::ROOT:partial$pr-preview.adoc[]


== What you will do and why

*Goal: Turn installed operators into usable services.*
A platform service is a running capability that applications and developers consume. You will create the browser IDE, OpenShift AI model-serving components, the Models-as-a-Service (MaaS) gateway and trace storage. MaaS puts one governed API in front of models: callers use a client API key and token allowance rather than the cloud provider’s account key. These services are shared prerequisites for the developer, not code that the developer must rebuild in every app.


*Platform Engineer · bastion terminal.* Operators reconcile instances; installing a subscription alone does not create an IDE or model platform. Enable the services now that the additional workers are ready. These are direct CLI calls against the supplied manifests.

== Which services are being enabled?

[cols="1,2,2",options="header"]
|===
| Capability | What starts | Why it matters for the app
| Browser development | Dev Spaces and its workspace controller | The developer gets an editor and tools without configuring a laptop.
| Model serving | OpenShift AI, KServe, NFD and the NVIDIA ClusterPolicy | KServe will start D3; the GPU components make the T4 allocatable.
| Governed model access | MaaS, an HTTPS gateway, Authorino and PostgreSQL | Developers receive a client key and allowance, while provider keys remain on the platform.
| Agent and evidence | Gen AI studio, OGX, MLflow and monitoring | The app can use tools and expose a trace that proves what happened.
|===

The *DataScienceCluster (DSC)* is the administrator’s OpenShift AI configuration.
Its operator turns enabled components into running controllers and services.
This is created once here; the `dev` user will not recreate it in Dev Spaces.

This setup targets a fresh lab; it does not migrate an existing ephemeral database.

== Bind the MaaS gateway to this cluster

Read the actual apps domain and ingress certificate; there are no cluster IDs to replace.

include::ROOT:partial$run-bastion.adoc[]

[source,sh,role=execute]
----
# Read the cluster’s actual application domain, rather than copying another lab’s URL.
APPS_DOMAIN=$(oc get ingress.config.openshift.io cluster -o jsonpath='{.spec.domain}')
# Build the public MaaS hostname under that application domain.
MAAS_HOST="maas.${APPS_DOMAIN}"
# Read the configured ingress TLS Secret, or use the router’s default when none is named.
INGRESS_CERT=$(oc get ingresscontroller default -n openshift-ingress-operator \
  -o jsonpath='{.spec.defaultCertificate.name}')
# Read the configured ingress TLS Secret, or use the router’s default when none is named.
INGRESS_CERT=${INGRESS_CERT:-router-certs-default}
# Confirm the named Secret exists; this command does not decode or print its credentials.
oc get secret "$INGRESS_CERT" -n openshift-ingress

# Build a JSON patch using this cluster’s host and certificate names.
GATEWAY_PATCH=$(jq -cn --arg host "$MAAS_HOST" --arg cert "$INGRESS_CERT" '[
  {op:"replace",path:"/spec/listeners/0/hostname",value:$host},
  {op:"replace",path:"/spec/listeners/0/tls/certificateRefs/0/name",value:$cert}
]')
# Bind the MaaS HTTPS listener to this cluster’s host and ingress certificate.
oc patch gateway maas-default-gateway -n openshift-ingress --type=json -p "$GATEWAY_PATCH"
# Expose the HTTPS gateway through a TLS-passthrough OpenShift Route.
oc create route passthrough maas-gateway -n openshift-ingress \
  --service=maas-default-gateway-openshift-default --hostname="$MAAS_HOST" \
  --port=https --insecure-policy=Redirect --dry-run=client -o yaml | oc apply -f -
----

The passthrough Route sends ARO wildcard DNS traffic to the HTTPS gateway. The provider model is not deployed yet.

The patch sets the listener hostname and the certificate reference from the
values just read. `passthrough` forwards TLS to the gateway; `Redirect` upgrades
plain HTTP. This is gateway access for the external DeepSeek model; it does not
make the local D3 endpoint public.

== Trust the cluster service CA

Authorino authenticates MaaS requests and calls internal HTTPS services. Enable the service-CA-signed Authorino listener and trust the service CA for its outbound callbacks. The JSON patch preserves any existing volumes.

include::ROOT:partial$run-bastion.adoc[]

[source,sh,role=execute]
----
# Wait for the authentication service deployment to exist before configuring it.
oc wait --for=create deployment/authorino -n kuadrant-system --timeout=600s
# Record the serving-certificate or bootstrap setting used by the gateway authentication
# service.
oc annotate service authorino-authorino-authorization -n kuadrant-system \
  service.beta.openshift.io/serving-cert-secret-name=authorino-server-cert --overwrite
# Configure Authorino’s TLS or service-CA trust for internal HTTPS callbacks.
oc patch authorino authorino -n kuadrant-system --type=merge \
  -p '{"spec":{"listener":{"tls":{"enabled":true,"certSecretRef":{"name":"authorino-server-cert"}}}}}'
# Record the serving-certificate or bootstrap setting used by the gateway authentication
# service.
oc annotate gateway maas-default-gateway -n openshift-ingress \
  security.opendatahub.io/authorino-tls-bootstrap=true --overwrite
# Build a CA-volume patch that preserves any existing Authorino volumes.
oc get authorino authorino -n kuadrant-system -o json | jq '{spec:{volumes:
  ((.spec.volumes // {}) | .items =
    ((.items // [] | map(select(.name != "workshop-service-ca"))) + [{
      name:"workshop-service-ca",mountPath:"/etc/ssl/certs/openshift-service-ca",
      configMaps:["openshift-service-ca.crt"],
      items:[{key:"service-ca.crt",path:"service-ca-bundle.crt"}]
    }]))
}}' > state/authorino-service-ca.json
# Configure Authorino’s TLS or service-CA trust for internal HTTPS callbacks.
oc patch authorino authorino -n kuadrant-system --type=merge \
  --patch-file=state/authorino-service-ca.json
# Make Authorino trust the mounted cluster service CA on outbound TLS requests.
oc set env deployment/authorino -n kuadrant-system \
  SSL_CERT_FILE=/etc/ssl/certs/openshift-service-ca/service-ca-bundle.crt \
  REQUESTS_CA_BUNDLE=/etc/ssl/certs/openshift-service-ca/service-ca-bundle.crt
# Wait for the named deployment’s new pods to become available within the displayed timeout.
oc rollout status deployment/authorino -n kuadrant-system --timeout=180s
----

Gateway API CRDs were prepared in Lab 1.1. Kuadrant can reconcile its filters without recycling its controller.

[IMPORTANT]
====
*Initial service startup usually takes 5–15 minutes.* PostgreSQL’s first wait
allows 5 minutes; OpenShift AI initialization/component waits each allow 20
minutes; MLflow’s first migration and startup allow 15 minutes. Output that says
`Waiting for ...` is expected during downloads and reconciliation. A timeout is
not success: inspect the named resource and its pod events before continuing.
====

  SSL_CERT_FILE=/etc/ssl/certs/openshift-service-ca/service-ca-bundle.crt \
  REQUESTS_CA_BUNDLE=/etc/ssl/certs/openshift-service-ca/service-ca-bundle.crt
# Wait for the named deployment’s new pods to become available within the displayed timeout.

# Wait until the HTTPS gateway has been programmed.
oc wait gateway/maas-default-gateway -n openshift-ingress --for=condition=Programmed --timeout=600s
# Wait for the browser IDE platform to become Active.
oc wait checluster/devspaces -n openshift-operators --for=jsonpath='{.status.chePhase}'=Active --timeout=900s
# Wait for the NVIDIA driver/device plugin to advertise one allocatable GPU.

The cluster now has an IDE, delivery operators, the model platform and one allocatable GPU. Stop after any readiness failure; inspect Pending pods, operator conditions and capacity. No model is deployed yet.

== Cache the workspace images

Workspace images include a multi-gigabyte developer toolchain. Without a cache,
the first developer has to wait for that download after opening the workspace.
Caching moves the download into platform preparation, while the next model labs
are running. It speeds up the handoff; it does not eliminate first-time home
initialization or storage setup.

Start the documented https://docs.redhat.com/en/documentation/red_hat_openshift_dev_spaces/3.28/html/administration_guide/assembly_caching-images-for-faster-workspace-start_administration_guide[Kubernetes Image Puller] now. It downloads the developer, editor, OpenCode and test-browser images on CPU workers while you prepare the models. Lab 1.1 installs its operator. Read the editor image from the installed Dev Spaces version rather than maintaining another image version.

include::ROOT:partial$run-bastion.adoc[]

[source,sh,role=execute]
----
# Read the editor image supplied by the installed Dev Spaces operator version.
EDITOR_IMAGE=$(oc exec -n openshift-operators deployment/devspaces-operator -- \
  cat /tmp/external_images.txt | sed -n '\|/code-rhel9@|{p;q;}')
# Read the platform’s pinned OpenCode injector image from its tool registry.
OPENCODE_IMAGE=$(oc get configmap ai-tool-registry -n openshift-operators -o json | \
  jq -er '.data["registry.json"] | fromjson | .tools[] | select(.providerId=="opencodeai/opencode") | .injectorImage')
# Stop before patching the cache if the installed image names could not be discovered.
test -n "$EDITOR_IMAGE" && test -n "$OPENCODE_IMAGE"
# Configure image caching through the installed Dev Spaces instance.
oc patch checluster devspaces -n openshift-operators --type=merge -p \
  "$(jq -cn --arg images "dev=quay.io/devfile/universal-developer-image:latest;editor=${EDITOR_IMAGE};opencode=${OPENCODE_IMAGE};test-browser=mcr.microsoft.com/playwright:v1.56.1-noble" \
    '{spec:{components:{imagePuller:{enable:true,spec:{images:$images,cachingCPURequest:"10m"}}}}}')"
# Wait for the prerequisite object to exist before configuring or using it.
oc wait --for=create daemonset/kubernetes-image-puller -n openshift-operators --timeout=180s
# Inspect the named resource and its reported status before proceeding.
oc get daemonset kubernetes-image-puller -n openshift-operators
----

[IMPORTANT]
====
*Allow 3–10 minutes for the first cache download; slow registries can take longer.*
The initial DaemonSet `READY` count may be `0`. Leave it running during Labs
1.4–1.8. Lab 2.1 waits up to 10 minutes for all cache pods before opening Dev Spaces.
====

The first download still takes time; it happens before the developer starts. The GPU taint keeps this cache on CPU workers. Leave it running and continue with Foundry.
