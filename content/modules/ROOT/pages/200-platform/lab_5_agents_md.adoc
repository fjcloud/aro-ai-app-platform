= Lab 1.5 — Hand the Keys

DeepSeek-V4 Pro is already answering. Your job now is to hand the afternoon developer a *launch URL* and a short runbook — not a wiki, not Ansible, not a tour of every Kustomize file.

The ARO transcription template is on its own branch: https://github.com/fjcloud/go-app-template/tree/aro-transcription[fjcloud/go-app-template].

[NOTE]
====
*Estimated time:* 10 minutes +
*Persona:* Platform Engineer +
*Deliverable:* You have read `AGENTS.md`. You can paste the Dev Spaces URL to Act 2.
====

== What the developer actually gets

[cols="1,2", options="header"]
|===
| Path | Why it exists

| `AGENTS.md`
| The only runbook OpenCode reads. Generate `main.go` / `go.mod` / `Dockerfile`, then git, ephemeral Git, and `oc`.

| `opencode.json`
| The template still names the old model. Lab 2.1 overwrites it so the project pin is `deepseek/deepseekv4pro`. The key and base URL stay `$OPENAI_API_KEY` and `$OPENAI_BASE_URL`.

| `devfile.yaml`
| Dev Spaces workspace. Installs the ephemeral Git client.

| `deploy/` `pipeline/` `gitops/`
| Golden-path Kustomize. The model applies it; it must not rewrite it (except the Deployment `image:` at deploy time).
|===

There is no `scripts/` directory and no Ansible. DeepSeek-V4 Pro follows `AGENTS.md`.

== Step 1: Read AGENTS.md

Clone only if you want it on disk. On a shared workshop cluster you can also open the file on GitHub. Either way, *read it* — it is short.

[source,sh,role=execute]
----
git clone --depth 1 --branch aro-transcription https://github.com/fjcloud/go-app-template "$HOME/aro-transcription-template"
wc -l "$HOME/aro-transcription-template/AGENTS.md"
cat "$HOME/aro-transcription-template/AGENTS.md"
----

You should see a short file. Notice:

* *Files YOU must generate* — `main.go`, `go.mod`, `Dockerfile` with an exact two-stage template
* *Files already in the repository* — do not rewrite `deploy/`, `pipeline/`, `gitops/`, or `devfile.yaml`
* *Three deploy phases* — ephemeral Git → Tekton PipelineRun → Argo CD Application
* *Namespaces* — `$\{APP_NAME}-build` and `$\{APP_NAME}-dev` only. Never namespace `default` for the app, Argo CD, or the Application.

[cols="1,2,2", options="header"]
|===
| Phase | What it does | Typical duration

| 1. Git
| Create a personal repo on ephemeral Git, commit, and push
| ~30s

| 2. Image
| `oc apply -k pipeline/base` and a Tekton `PipelineRun` (git-clone + buildah)
| 3–5 min

| 3. GitOps
| Point `image:` at the built image, `oc apply -k gitops/base`, create the Argo CD `Application`
| 2–3 min
|===

== Step 2: Confirm OpenCode is wired to Foundry

OpenCode is injected from the AI tool registry you applied in Lab 1.3. The *binary* comes from the platform. The platform model pin is the ConfigMap. The *project* file in the template wins once the workspace opens, which is why Lab 2.1 rewrites it.

[source,sh,role=execute]
----
oc get configmap opencode-workspace-config -n openshift-operators \
  -o jsonpath='{.data.opencode\.json}' | python3 -m json.tool
----

You should see `baseURL` `{env:OPENAI_BASE_URL}`, an `api-key` header, provider name `DeepSeek-V4 Pro`, model id `deepseekv4pro`, and `"model": "deepseek/deepseekv4pro"`.

== Step 3: Copy the developer launch URL

[source,sh,role=execute]
----
DEVSPACES_URL=$(oc get checluster -A -o jsonpath='{.items[0].status.cheURL}')
if [[ -z "$DEVSPACES_URL" ]]; then
  DEVSPACES_URL="https://$(oc get route devspaces -n openshift-operators \
    -o jsonpath='{.spec.host}')"
fi
TEMPLATE_URL="https://github.com/fjcloud/go-app-template/tree/aro-transcription"

echo "============================================"
echo " Participant workspace URL:"
echo "  $DEVSPACES_URL/#$TEMPLATE_URL?ai-provider=opencodeai/opencode"
echo "============================================"
----

When a developer opens that URL, Dev Spaces clones the template, injects the OpenCode binary, installs the ephemeral Git client, and opens VS Code in the browser. Lab 2.1 points the project at DeepSeek-V4 Pro. `AGENTS.md` is the runbook, including the browser audio and Whisper API contract.
