== What the developer actually gets

[cols="1,2", options="header"]
|===
| Path | Why it exists

| `AGENTS.md`
| Short instructions: generate, run the supplied acceptance tests, fix app failures, then ship.

| `APP_CONTRACT.md`
| The minimal page, proxy API and stable test hooks.

| `DELIVERY.md`
| Build and delivery commands, read when shipping.

| `tests/`
| Fixed acceptance tests with fixture data, plus the real-platform check.

| `opencode.json`
| The template pins `deepseek/deepseekv4pro`. The key and base URL stay `$OPENAI_API_KEY` and `$OPENAI_BASE_URL`.

| `devfile.yaml`
| Dev Spaces workspace with the ephemeral Git client and a local-only test browser.

| `deploy/` `pipeline/` `gitops/`
| Golden-path Kustomize. The Deployment already names the internal Tekton image. The pipeline validates that image before building; the model keeps the scaffold intact.
|===

`APP_CONTRACT.md` defines the application, APIs and acceptance checks. `AGENTS.md` defines the short test-and-fix workflow; `DELIVERY.md` contains the detailed delivery commands. There is no app `scripts/` directory and no Ansible.

== Prepare the developer's permissions

Prepare the two application namespaces and inject a scoped developer identity into Dev Spaces. This helper waits for namespace security allocation, creates the limited permissions and mounts a temporary kubeconfig without printing its token.

Run from the bastion before opening Dev Spaces:

[source,sh,role=execute]
----
python3 scripts/prepare-developer.py
oc auth can-i create pipelineruns -n card-scout-build \
  --as=system:serviceaccount:card-scout-dev:workshop-developer
----

The developer can build and deploy in the two application namespaces. They cannot create namespaces, change SCCs or create cluster-wide bindings. Image-pull permission is prepared here, not by the model. The Pipelines operator supplies its standard, non-privileged build service account permissions.

The injected developer token is valid for 24 hours. Preparation must run before opening Dev Spaces; restart an existing workspace to receive the scoped kubeconfig.

== Step 1: Read AGENTS.md

Clone only if you want it on disk. On a shared workshop cluster you can also open the file on GitHub. Either way, *read it* — it is short.

[source,sh,role=execute]
----
git clone --depth 1 --branch aro-card-scout https://github.com/fjcloud/go-app-template "$HOME/card-scout-template"
wc -l "$HOME/card-scout-template/AGENTS.md"
cat "$HOME/card-scout-template/AGENTS.md"
cat "$HOME/card-scout-template/APP_CONTRACT.md"
----

The app contract stays small. OpenCode must run `npm test`, fix the application
until it passes and keep the supplied tests unchanged. The detailed Git → Tekton
→ Argo CD commands remain in `DELIVERY.md` for the shipping phase.

== Step 2: Confirm OpenCode is wired to MaaS

OpenCode is injected from the AI tool registry enabled in Lab 1.3. The *binary* comes from the platform. The platform model pin is the ConfigMap. The project and platform files both pin DeepSeek through MaaS. Lab 2.1 checks they agree.

[source,sh,role=execute]
----
oc get configmap opencode-workspace-config -n openshift-operators \
  -o jsonpath='{.data.opencode\.json}' | jq .
----

You should see `baseURL` `{env:OPENAI_BASE_URL}`, Bearer authentication, provider name `DeepSeek-V4 Pro`, model id `deepseekv4pro`, and `"model": "deepseek/deepseekv4pro"`.
