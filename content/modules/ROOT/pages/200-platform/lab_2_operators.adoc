= Lab 1.2 — Install Platform Operators

Install the operators the afternoon needs, from the manifests in this repo. The model is already the Foundry endpoint from Lab 1.1. Do not install a GPU node pool, and do not apply `deploy/inference`.

Trigger the apply and move on. Lab 1.3 waits for Dev Spaces, GitOps, and Pipelines before it stores the Foundry key.

[NOTE]
====
*Estimated time:* 5 minutes active + ~20 minutes background installation +
*Persona:* Platform Engineer +
*Fire and forget:* Trigger the installs, then move immediately to Lab 1.3 while they complete.
====

== Step 1: Install the operators

From the workshop repository you cloned in Act 0:

[source,sh,role=execute]
----
oc apply -f deploy/operators/devspaces-subscription.yaml
oc apply -f deploy/operators/gitops-namespace.yaml \
  -f deploy/operators/gitops-operatorgroup.yaml \
  -f deploy/operators/gitops-subscription.yaml
oc apply -f deploy/operators/pipelines-subscription.yaml
----

.Sample Output

The Tekton `git-clone` and `buildah` tasks are applied at the start of Lab 1.3, after the Pipeline CRDs exist.

== Step 2: Start Background Health Checks

`oc wait` exits immediately if the Deployment does not exist yet. Wait for OLM to create it first:

[source,sh,role=execute]
----
for check in \
  "openshift-operators:devspaces-operator:Dev Spaces" \
  "openshift-gitops:openshift-gitops-server:GitOps (Argo CD)" \
  "openshift-pipelines:tekton-pipelines-controller:Pipelines (Tekton)"; do
  IFS=: read ns dep label <<< "$check"
  (
    until oc get deployment/${dep} -n ${ns} >/dev/null 2>&1; do sleep 5; done
    oc wait deployment/${dep} -n ${ns} \
      --for=condition=Available --timeout=600s &&
    echo "  ✅  ${label} ready"
  ) &
done

echo "Operator checks running in background — move on to Lab 1.3."
----

== What is Happening Under the Hood

OLM resolves each `Subscription`, installs CRDs and RBAC, then deploys the operator pod:

----
Subscription → InstallPlan → CRDs → RBAC → Operator Pod → Succeeded
----
