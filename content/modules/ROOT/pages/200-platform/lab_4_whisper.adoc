= Lab 1.4 — Serve Whisper on one T4

Keep DeepSeek on Foundry for OpenCode. Add a separate speech model for the application: *RedHatAI Whisper Large v3 Turbo INT8*, served by *Red Hat AI Inference 3.5* on *OpenShift AI 3.5 / KServe*, using one NVIDIA T4.

[NOTE]
====
*Persona:* Platform Engineer +
*Time:* ~15 minutes active; allow 25–40 minutes for a new worker, driver and first image/model download. +
*Requires:* Classic ARO, cluster-admin, Azure VM permissions, T4 quota and capacity. Keep the existing CPU workers. Allow CPU headroom for OpenShift AI, Dev Spaces and Tekton; three small D4 workers can run out of schedulable CPU. If a workspace is Pending, check its events and provision additional CPU capacity in the zone of its PVC.
====

== Why this model

The https://access.redhat.com/articles/rhoai-supported-configs[OpenShift AI support matrix] includes ARO and OpenShift 4.21 for OpenShift AI 3.5. The https://docs.redhat.com/en/documentation/red_hat_ai/3/html-single/supported_product_and_hardware_configurations/index[Red Hat AI hardware matrix] includes the T4 for the CUDA runtime and *INT8 W8A8*. Use https://huggingface.co/RedHatAI/whisper-large-v3-turbo-quantized.w8a8[RedHatAI/whisper-large-v3-turbo-quantized.w8a8], without custom kernels. The INT4 and FP8 W8A8 variants are not the supported T4 path. The runtime image and model revision are pinned in `deploy/speech/servingruntime.yaml`.

The inference runtime is a Red Hat product. The Whisper weights are published by the *RedHatAI* Hugging Face organization as an INT8 quantization of OpenAI Whisper. `--dtype=half` applies to non-quantized operations; vLLM detects INT8 from the model’s quantization configuration. This workshop does not imply certification of the generated application or a blanket support guarantee for every model/configuration; production support requires the appropriate subscriptions and supported hardware/operator versions.

== Inspect the cluster and worker pools

Run these commands in the bastion terminal, from the workshop checkout. Classic ARO adds worker pools with OpenShift MachineSets, following the https://learn.microsoft.com/en-us/azure/openshift/howto-gpu-workloads[Microsoft GPU guide]. The `az aro hcp cluster nodepool` commands belong to ARO HCP. This lab shows the actual pool definitions and CLI calls directly.

[source,sh,role=execute]
----
source state/workshop.env
set -o pipefail
ARO_NAME="${ARO_CLUSTER_ID##*/}"
INFRA=$(oc get infrastructure cluster -o jsonpath='{.status.infrastructureName}')
REGION=$(az aro show --name "$ARO_NAME" --resource-group "$RESOURCEGROUP" \
  --subscription "$SUBSCRIPTION" --query location -o tsv)

oc get machinesets -n openshift-machine-api \
  -o 'custom-columns=NAME:.metadata.name,SIZE:.spec.template.spec.providerSpec.value.vmSize,ZONE:.spec.template.spec.providerSpec.value.zone,DESIRED:.spec.replicas,READY:.status.readyReplicas'
oc get pv -o 'custom-columns=CLAIM:.spec.claimRef.name,NAMESPACE:.spec.claimRef.namespace,ZONE:.spec.nodeAffinity.required.nodeSelectorTerms[*].matchExpressions[*].values'
----

Keep the original CPU pools. If a workshop CPU or T4 pool already exists, reuse it and skip its creation block below. Confirm its VM size and replica count in the table first.

=== Check Azure quota and GPU zones

[source,sh,role=execute]
----
az vm list-usage --location "$REGION" --subscription "$SUBSCRIPTION" \
  --query "[?name.value=='cores' || name.value=='standardDSv3Family' || contains(name.value, 'T4')].{quota:name.localizedValue,used:currentValue,limit:limit}" -o table
az vm list-skus --location "$REGION" --subscription "$SUBSCRIPTION" \
  --resource-type virtualMachines --size Standard_NC8as_T4_v3 --all \
  --query '[].{size:name,zones:locationInfo[0].zones,restrictions:restrictions}' -o json
----

The SKU lookup can take a few minutes. A new D8 CPU worker needs 8 free DSv3 vCPUs; a new T4 worker needs 8 free NCasT4_v3 vCPUs. Creating both needs 16 free regional vCPUs. The chosen GPU zone must be listed and unrestricted; quota does not guarantee available VM capacity.

== Add one CPU worker when needed

Three small D4 workers can run out of schedulable CPU with OpenShift AI, Dev Spaces and Tekton. If more headroom is needed, add one `Standard_D8s_v3` worker. Choose a zone containing an original CPU MachineSet. An existing Dev Spaces PVC requires CPU capacity in its own zone; adapt `CPU_ZONE=3` to the PV table above. Skip this step if the cluster already has enough capacity.

[source,sh,role=execute]
----
CPU_ZONE=3
CPU_TEMPLATE=$(oc get machinesets -n openshift-machine-api -o json |
  jq -er --arg zone "$CPU_ZONE" '
    [.items[] | select(.spec.template.spec.providerSpec.value.zone == $zone)
     | select(.spec.template.spec.providerSpec.value.vmSize | startswith("Standard_D"))]
    | sort_by(.metadata.name) | .[0].metadata.name // error("No CPU template in this zone")
  ')
CPU_POOL="${INFRA}-speech-cpu-${REGION}${CPU_ZONE}"

oc get machineset "$CPU_TEMPLATE" -n openshift-machine-api -o json | \
  jq --arg name "$CPU_POOL" '
    del(.status)
    | .metadata = {name: $name, namespace: "openshift-machine-api",
        labels: {"workshop.fjcloud.io/speech-capacity": "true"}}
    | .spec.replicas = 1
    | .spec.selector.matchLabels["machine.openshift.io/cluster-api-machineset"] = $name
    | .spec.template.metadata.labels["machine.openshift.io/cluster-api-machineset"] = $name
    | .spec.template.spec.providerSpec.value.vmSize = "Standard_D8s_v3"
  ' | oc create -f -

oc wait machineset/"$CPU_POOL" -n openshift-machine-api \
  --for=jsonpath='{.status.readyReplicas}'=1 --timeout=1200s
----

The new MachineSet inherits the cluster’s image, subnet, disks and bootstrap configuration. The original pools are unchanged. `replicas = 1` creates one additional worker, with its own hourly cost. Repeating `oc create` reports *AlreadyExists* for the same pool.

== Step 1: Add one T4 worker

Use `Standard_NC8as_T4_v3`: one 16 GB T4, 8 vCPUs and 56 GiB RAM. Set `GPU_ZONE` to an available zone from the Azure output above that also has an original CPU MachineSet. The GPU zone may differ from the Dev Spaces PVC zone.

[source,sh,role=execute]
----
GPU_ZONE=1
GPU_TEMPLATE=$(oc get machinesets -n openshift-machine-api -o json |
  jq -er --arg zone "$GPU_ZONE" '
    [.items[] | select(.spec.template.spec.providerSpec.value.zone == $zone)
     | select(.spec.template.spec.providerSpec.value.vmSize | startswith("Standard_D"))]
    | sort_by(.metadata.name) | .[0].metadata.name // error("No CPU template in this zone")
  ')
GPU_POOL="${INFRA}-gpu-t4-8-${REGION}${GPU_ZONE}"

oc get machineset "$GPU_TEMPLATE" -n openshift-machine-api -o json | \
  jq --arg name "$GPU_POOL" '
    del(.status)
    | .metadata = {name: $name, namespace: "openshift-machine-api",
        labels: (.metadata.labels + {"workshop.fjcloud.io/experiment": "t4"})}
    | .spec.replicas = 1
    | .spec.selector.matchLabels["machine.openshift.io/cluster-api-machineset"] = $name
    | .spec.template.metadata.labels["machine.openshift.io/cluster-api-machineset"] = $name
    | .spec.template.spec.metadata.labels["workshop.fjcloud.io/gpu"] = "t4"
    | .spec.template.spec.taints = [{key: "nvidia.com/gpu", value: "present", effect: "NoSchedule"}]
    | .spec.template.spec.providerSpec.value.vmSize = "Standard_NC8as_T4_v3"
  ' | oc create -f -

oc wait machineset/"$GPU_POOL" -n openshift-machine-api \
  --for=jsonpath='{.status.readyReplicas}'=1 --timeout=1200s
oc get machines -n openshift-machine-api
oc get nodes -l workshop.fjcloud.io/gpu=t4
----

The taint reserves the worker for workloads that explicitly tolerate `nvidia.com/gpu=present:NoSchedule`. Node readiness confirms provisioning; the NVIDIA operator in Step 2 makes the GPU available to pods. Do not substitute a four-T4 `NC64` size: requesting one GPU in a pod still incurs the cost of the entire VM.

== Step 3: Enable OpenShift AI model serving

[source,sh,role=execute]
----
oc apply -f deploy/instances/rhoai-dsci.yaml
oc apply -f deploy/speech/rhoai-dsc.yaml
oc wait dsc/default-dsc --for=condition=Ready --timeout=900s
oc apply -k deploy/speech
oc wait inferenceservice/whisper -n speech-serving \
  --for=condition=Ready --timeout=1800s
----

This enables the dashboard and KServe. It does not deploy the historical Qwen/MaaS stack. Do not apply `deploy/instances` or `deploy/inference` as a whole.

[source,sh,role=execute]
----
oc get inferenceservice,servingruntime,pvc -n speech-serving
oc get pods -n speech-serving
oc get route -n speech-serving
----

Expect a Ready `whisper` inference service and *no public model Route*. The internal endpoint is:

[source,text]
----
http://whisper-predictor.speech-serving.svc.cluster.local/v1/audio/transcriptions
----

KServe publishes the service on port 80 and forwards to vLLM on 8080. The network policy allows the `live-transcript-dev` application namespace and Dev Spaces workspaces to reach the model. The browser contacts only the Go app over HTTPS; the backend forwards audio to Whisper without exposing a model endpoint or credentials to browser code.

Open the *Red Hat OpenShift AI* link in the OpenShift application launcher. In *Projects*, select *Workshop speech transcription* and inspect the Whisper deployment. The dashboard is the management view; it is not a second coding endpoint.

== Step 4: Understand the audio path

image::model-serving-architecture.png[Go backend to internal Whisper serving on one T4, align="center"]

[source,text]
----
Microphone → AudioWorklet → independent 16 kHz PCM16 WAV clips
           → Go POST /api/transcribe → KServe / vLLM → Whisper
           ← transcript JSON        ← model output
----

The app sends short clips sequentially, displays each result and flushes the last clip on Stop. This provides *near-real-time* transcription, with a delay from capture plus inference. It is not native Whisper WebSocket streaming. WAV avoids the problem of later WebM recorder slices not being independently decodable.

The application keeps audio in memory, skips silence, bounds uploads and queued clips, and stops the microphone on Stop or failure. It requires browser microphone permission and the HTTPS application Route. Do not record sensitive conversations in a shared demo environment.
