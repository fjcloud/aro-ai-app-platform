= Lab 1.8 — Prepare the Signal Desk Agent
:page-aliases: 200-platform/lab_6_cluster_voice.adoc

The decision model scores relevance. The runtime agent researches possible company stock exposure through *OpenShift AI's native Responses API*. Prepare that second path before the developer builds the app.

[NOTE]
====
*Persona:* Platform Engineer +
*Time:* 10–15 minutes after MLflow is ready +
*Outcome:* Fixed model endpoints, separate runtime key, app identity, storage and trace experiment.
====

== Deploy the native Responses backend

Create https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html/working_with_ogx/deploying-ogx-server_rag[`OGXServer/lsd-genai-playground`] explicitly in `signal-desk-dev`. The OpenShift AI operator creates its Deployment and Service using the Red Hat OGX image. The configuration points to the existing MaaS DeepSeek model; it contains no model key.

From the bastion, update the checkout and apply the backend resources:

[source,sh,role=execute]
----
git pull --ff-only
MAAS_URL="https://maas.$(oc get ingress.config.openshift.io cluster -o jsonpath='{.spec.domain}')/v1"
oc create configmap signal-desk-agent-endpoint -n signal-desk-dev \
  --from-literal=MAAS_URL="$MAAS_URL" --dry-run=client -o yaml | oc apply -f -
oc apply -k deploy/briefing/agent
oc wait ogxserver/lsd-genai-playground -n signal-desk-dev \
  --for=jsonpath='{.status.phase}'=Ready --timeout=600s
oc rollout status deployment/lsd-genai-playground -n signal-desk-dev --timeout=600s
oc get deployment lsd-genai-playground -n signal-desk-dev
oc get service lsd-genai-playground-service -n signal-desk-dev
oc get pods -n signal-desk-dev
oc get mlflow mlflow -o json | jq '{conditions:.status.conditions,url:.status.url}'
----

Continue only when the backend is Ready in `signal-desk-dev`. A Playground created in another project does not provide the application endpoint. The first Red Hat image pull can take several minutes; inspect `oc describe ogxserver lsd-genai-playground -n signal-desk-dev` and pod events if a wait times out.

The bundled configuration uses local SQLite/FAISS storage; Playground session history is temporary. The app's saved news and paper portfolio use their own persistent volume below. OpenShift AI's Playground is used later to test the prepared agent, not to provision it.

The runtime application calls:

[source,text]
----
http://lsd-genai-playground-service.signal-desk-dev.svc.cluster.local:8321/v1/responses
model: maas-vllm-inference-1/deepseekv4pro
----

The NetworkPolicy applied below permits the Dev Spaces namespaces to reach only the native API port (8321), without editing the operator-owned policy or opening its metrics port.

This is the native OpenShift AI agent backend. OpenCode uses the MaaS Chat Completions endpoint for coding; the app uses Responses for model/tool turns. Both reach the same DeepSeek deployment, with separate MaaS credentials.

== Create application resources

Apply the manifests for the app identity, service CA, 2 GiB data volume, image-pull permissions, MaaS subscription and Dev Spaces network access:

[source,sh,role=execute]
----
oc apply -k deploy/briefing
oc wait maassubscription/deepseekv4pro-signal-desk -n models-as-a-service \
  --for=condition=Ready --timeout=180s
oc get serviceaccount,pvc -n signal-desk-dev
----

== Configure credentials and tracing

Use a helper for the dynamic API calls: mint the separate runtime key, find or create the MLflow experiment, and wire their returned values into the app configuration and Playground MCP catalog.

[source,sh,role=execute]
----
python3 scripts/prepare-briefing-desk.py
oc get serviceaccount signal-desk -n signal-desk-dev
oc get configmap signal-desk-config -n signal-desk-dev -o json | jq .data
oc get secret signal-desk-model -n signal-desk-dev
oc get pvc signal-desk-data -n signal-desk-dev
----

The runtime identity gets no cluster-monitoring or workload-editing permissions. The key expires after 24 hours; rerun the helper and restart the application if the lab continues longer. A `Pending` app data PVC is expected before deployment: `managed-csi` waits for its first consuming pod.

The app and read-only MCP tools are public over HTTPS, with no separate Signal Desk login. Model keys remain in backend Secrets.

The application is *Signal Desk*: `signal-desk-dev` hosts the app and agent, and `signal-desk-build` hosts its build pipeline and images. Keep these names when generating the app.

== The application contract

Read `APP_CONTRACT.md` in the template. The backend owns five simple responsibilities:

. Read the dated Techmeme news snapshot bundled with the application.
. Preserve its source dates, cutoff and collection provenance.
. Score the archived news against the fund memo with d3-mini.
. Ask DeepSeek for hypothetical long-only company stock exposures using bounded archive and company-reference tools.
. Freeze the virtual portfolio, then compare its entry price with the latest available market quote.

[source,text]
----
Repository news JSON → Go app → d3-mini /v1/systemone → relevance /100
                       └→ OpenShift AI /v1/responses → DeepSeek / MaaS
                               ↕ read_archive / search_archive / search_companies

Browser → $10,000 paper allocation → freeze → latest market quote → result
Playground → public MCP /mcp → the same read-only archive/catalog
Agent and scoring calls → OpenTelemetry → MLflow
Git → Tekton → Argo CD → same Go app
----

The model cannot fetch this week's prices during research. Prices are requested by deterministic Go code only after commitment and include the quote timestamp. Archived snippets are not full publisher articles; scoring relevance is not predicting profit. Historical replay cannot erase knowledge from model training, so this is not a blind backtest.
