= Lab 1.8 — Prepare Card Scout
:page-aliases: 200-platform/lab_6_cluster_voice.adoc

Prepare the mixed-era card dataset, local image classification and a native OpenShift AI agent that verifies catalogue references and retrieves dated market prices. The developer will generate only a small Go UI and proxy.

[NOTE]
====
*Persona:* Platform Engineer +
*Time:* 10–15 minutes after MLflow is ready +
*Outcome:* Fixed model endpoints, separate runtime key, app identity, storage and trace experiment.
====

== Deploy the native Responses backend

Create https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html/working_with_ogx/deploying-ogx-server_rag[`OGXServer/lsd-genai-playground`] explicitly in `signal-desk-dev`. The OpenShift AI operator creates its Deployment and Service using the Red Hat OGX image. The configuration points to the existing MaaS DeepSeek model; it contains no model key.

From the bastion, update the checkout and apply the backend resources:

[source,sh,role=execute]
----
git pull --ff-only
MAAS_URL="https://maas.$(oc get ingress.config.openshift.io cluster -o jsonpath='{.spec.domain}')/v1"
oc create configmap signal-desk-agent-endpoint -n signal-desk-dev \
  --from-literal=MAAS_URL="$MAAS_URL" --dry-run=client -o yaml | oc apply -f -
oc apply -k deploy/briefing/agent
oc wait ogxserver/lsd-genai-playground -n signal-desk-dev \
  --for=jsonpath='{.status.phase}'=Ready --timeout=600s
oc rollout status deployment/lsd-genai-playground -n signal-desk-dev --timeout=600s
oc get deployment lsd-genai-playground -n signal-desk-dev
oc get service lsd-genai-playground-service -n signal-desk-dev
oc get pods -n signal-desk-dev
oc get mlflow mlflow -o json | jq '{conditions:.status.conditions,url:.status.url}'
----

Continue only when the backend is Ready in `signal-desk-dev`. A Playground created in another project does not provide the application endpoint. The first Red Hat image pull can take several minutes; inspect `oc describe ogxserver lsd-genai-playground -n signal-desk-dev` and pod events if a wait times out.

The bundled configuration uses local SQLite/FAISS storage; Playground session history is temporary. Card Scout stores analysis and research results in a separate persistent volume. OpenShift AI's Playground is used later to test the prepared agent, not to provision it.

The runtime application calls:

[source,text]
----
http://lsd-genai-playground-service.signal-desk-dev.svc.cluster.local:8321/v1/responses
model: maas-vllm-inference-1/deepseekv4pro
----

The NetworkPolicy applied below permits the Dev Spaces namespaces to reach only the native API port (8321), without editing the operator-owned policy or opening its metrics port.

This is the native OpenShift AI agent backend. OpenCode uses the MaaS Chat Completions endpoint for coding; the app uses Responses for model/tool turns. Both reach the same DeepSeek deployment, with separate MaaS credentials.

== Create application resources

Apply the manifests for the app identity, service CA, image-pull permissions, MaaS subscription and Dev Spaces network access:

[source,sh,role=execute]
----
oc apply -k deploy/briefing
oc wait maassubscription/deepseekv4pro-signal-desk -n models-as-a-service \
  --for=condition=Ready --timeout=180s
oc get serviceaccount,pvc -n signal-desk-dev
----

== Configure the prepared service

A helper handles the dynamic MaaS key and MLflow experiment APIs. The CLI then
applies the service manifests. Its prebuilt Red Hat UBI image includes the fixed
dataset and all 51 images; the lab does not download card images at startup.

[source,sh,role=execute]
----
python3 scripts/prepare-card-scout.py
oc apply -k deploy/card-scout
oc rollout status deployment/card-scout-platform -n signal-desk-dev --timeout=600s
oc get service card-scout-platform -n signal-desk-dev
oc get pvc card-scout-data -n signal-desk-dev
oc get configmap signal-desk-config -n signal-desk-dev -o json | jq .data
oc get secret signal-desk-model -n signal-desk-dev
----

The platform service owns the runtime model key, state and trace export. Its
service account receives MLflow integration access, with no monitoring or
workload-editing grant. The MaaS key expires after 24 hours; refresh it with the
helper and restart `card-scout-platform` if needed.

The generated Go app has no model key, Kubernetes token or storage volume. It
calls one internal API supplied as `CARD_SCOUT_URL`. Keep the technical name
`signal-desk` and the prepared namespaces so the delivery scaffold stays usable.

== Check the fixed dataset

[source,sh,role=execute]
----
CARD_HOST=$(oc get route card-scout-tools -n signal-desk-dev -o jsonpath='{.spec.host}')
curl --fail-with-body -sS "https://${CARD_HOST}/api/batch" |   jq '{dataset,running,completed,failed,first:.items[0]}'
----

Expect 48 Pokémon cards across eight eras, from 1999 to 2023, plus three controls.
Each era contributes common, uncommon and rare cards. Catalogue IDs are known
from this prepared collection. D3 sees only image bytes; reference labels are
held out. It does not identify the exact edition of an arbitrary uploaded photo.

[source,text]
----
Browser → generated Go UI/proxy → prepared Card Scout service
                                    ├→ fixed images → D3 on T4 → rarity ranking
                                    └→ native OGX Responses → DeepSeek through MaaS
                                                   ↕ read-only price MCP → TCGdex
Model and tool spans → MLflow
Git → Tekton → Argo CD → generated Go app
----

The price tool looks up the selected dataset reference and retains provider,
currency, update timestamp and variant information. The agent must call it before
answering. Displayed amounts come from that evidence, never from model prose.
A rare card is not necessarily valuable; a market aggregate is not a sale offer.

The public MCP endpoint and app have no extra login. The OpenShift AI Playground
still uses its normal OpenShift session and MaaS subscription.
