= Lab 1.6 — Prepare the Signal Desk Agent
:page-aliases: 200-platform/lab_6_cluster_voice.adoc

The decision model scores relevance. The runtime agent researches possible index exposure through *OpenShift AI's native Responses API*. Prepare that second path before the developer builds the app.

[NOTE]
====
*Persona:* Platform Engineer +
*Time:* 10–15 minutes after MLflow is ready +
*Outcome:* Fixed model endpoints, separate runtime key, OAuth identity, storage and trace experiment.
====

== Create the native Playground backend

Open *Red Hat OpenShift AI → Gen AI studio → AI asset endpoints*. Select project `live-transcript-dev`, choose the MaaS *DeepSeek-V4 Pro* model and *Add to playground*. Create the Playground and wait for its backend to be ready. Keep the model registered from MaaS; do not create a second Foundry endpoint or paste the Azure account key.

From the bastion, inspect the native backend:

[source,sh,role=execute]
----
oc get deployment lsd-genai-playground -n live-transcript-dev
oc get service lsd-genai-playground-service -n live-transcript-dev
oc get pods -n live-transcript-dev
oc get mlflow mlflow -o json | jq '{conditions:.status.conditions,url:.status.url}'
----

The runtime application calls:

[source,text]
----
http://lsd-genai-playground-service.live-transcript-dev.svc.cluster.local:8321/v1/responses
model: maas-vllm-inference-1/deepseekv4pro
----

This is the native OpenShift AI agent backend. OpenCode uses the MaaS Chat Completions endpoint for coding; the app uses Responses for model/tool turns. Both reach the same DeepSeek deployment, with separate MaaS credentials.

== Prepare runtime access

[source,sh,role=execute]
----
python3 scripts/prepare-briefing-desk.py
oc get serviceaccount signal-desk -n live-transcript-dev
oc get configmap signal-desk-config -n live-transcript-dev -o json | jq .data
oc get secret signal-desk-model signal-desk-oauth -n live-transcript-dev
oc get pvc signal-desk-data -n live-transcript-dev
----

The helper creates a dedicated app identity, an OpenShift OAuth proxy, a separate `deepseekv4pro-signal-desk` MaaS subscription/key, the `signal-desk` MLflow experiment and a 2 GiB data volume. The runtime identity gets no cluster-monitoring or workload-editing permissions. The key expires after 24 hours; rerun preparation and restart the application if the lab continues longer.

The fixed infrastructure name remains `live-transcript` for the prepared namespaces, registry image and pipeline. The exercise and browser UI are *Signal Desk*. Do not rename the delivery scaffold while generating the app.

== The application contract

Read `APP_CONTRACT.md` in the template. The backend owns four simple responsibilities:

. Collect the prior Monday–Sunday Techmeme archive and retain coverage gaps.
. Score the archived news against the fund memo with d3-mini.
. Ask DeepSeek for hypothetical long-only index exposures using bounded archive tools.
. Save and freeze the user's virtual portfolio, then calculate actual subsequent-week gross price returns.

[source,text]
----
Techmeme archive → Go app → d3-mini /v1/systemone → relevance /100
                       └→ OpenShift AI /v1/responses → DeepSeek / MaaS
                               ↕ read_archive / search_archive / index_universe

Browser → $10,000 paper allocation → freeze → historical prices → result
Playground → authenticated MCP /mcp → the same read-only archive/catalog
Agent and scoring calls → OpenTelemetry → MLflow
Git → Tekton → Argo CD → same Go app
----

The model cannot fetch this week's prices during research. Prices are requested by deterministic Go code only after commitment. A running week is visibly provisional. Archived snippets are not full publisher articles; scoring relevance is not predicting profit. Historical replay cannot erase knowledge from model training, so this is not a blind backtest.

== Test the native API before coding

Use the bastion, in a separate terminal, to forward the native service:

[source,sh,role=execute]
----
oc port-forward service/lsd-genai-playground-service -n live-transcript-dev \
  18321:8321 >/tmp/responses-port-forward.log 2>&1 &
RESPONSES_FORWARD_PID=$!
RUNTIME_KEY=$(oc get secret signal-desk-model -n live-transcript-dev \
  -o jsonpath='{.data.api-key}' | base64 -d)
PROVIDER_DATA=$(jq -cn --arg key "$RUNTIME_KEY" \
  '{"vllm_api_token":$key}')
curl --fail-with-body -sS --retry 10 --retry-connrefused --retry-delay 2 \
  --max-time 180 http://127.0.0.1:18321/v1/responses \
  -H 'Content-Type: application/json' \
  -H "X-OGX-Provider-Data: $PROVIDER_DATA" \
  -d '{"model":"maas-vllm-inference-1/deepseekv4pro","input":"Reply with one short sentence about research relevance.","store":false}' | jq .
unset RUNTIME_KEY PROVIDER_DATA
kill "$RESPONSES_FORWARD_PID"
----

The key stays in the shell and server-side Secret. It never belongs in the browser, Git or an OpenCode prompt. Continue only when the native API returns a model response.
