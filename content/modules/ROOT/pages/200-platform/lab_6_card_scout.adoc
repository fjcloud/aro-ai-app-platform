== Goal

Provide the fixed card dataset, image classification, native OpenShift AI agent, price tool and MLflow traces behind one API. The developer can then generate a small UI without rebuilding these services.

[NOTE]
====
*Persona:* Platform Engineer +
*Time:* 10–15 minutes after MLflow is ready +
*Outcome:* Fixed model endpoints, separate runtime key, app identity, storage and trace experiment.
====

== Deploy the native Responses backend

Create https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5/html/working_with_ogx/deploying-ogx-server_rag[`OGXServer/lsd-genai-playground`] explicitly in `card-scout-dev`. The OpenShift AI operator creates its Deployment and Service using the Red Hat OGX image. The configuration points to the existing MaaS DeepSeek model; it contains no model key.

From the cluster terminal, update the checkout and apply the backend resources:

include::ROOT:partial$run-cluster.adoc[]

[source,sh,role=execute]
----
# Update this checkout only if it can fast-forward; do not overwrite local changes.
git pull --ff-only
# Build the native agent’s model base URL from this cluster’s application domain.
MAAS_URL="https://maas.$(oc get ingress.config.openshift.io cluster -o jsonpath='{.spec.domain}')/v1"
# Record the native agent’s MaaS endpoint without placing a key in the ConfigMap.
oc create configmap card-scout-agent-endpoint -n card-scout-dev \
  --from-literal=MAAS_URL="$MAAS_URL" --dry-run=client -o yaml | oc apply -f -
# Wait for the prerequisite object to exist before configuring or using it.
oc wait --for=create configmap/odh-trusted-ca-bundle -n card-scout-dev --timeout=180s
# Allow the agent operator to watch the trusted-CA ConfigMap for updates.
oc label configmap odh-trusted-ca-bundle -n card-scout-dev ogx.io/watch=true --overwrite
# Create the native agent backend in card-scout-dev.
oc apply -k deploy/card-scout/agent
# Wait for the CLI-created native agent backend to become Ready.
oc wait ogxserver/lsd-genai-playground -n card-scout-dev \
  --for=jsonpath='{.status.phase}'=Ready --timeout=600s
# Wait for the deployment to become available.
oc rollout status deployment/lsd-genai-playground -n card-scout-dev --timeout=600s
# Inspect deployment status.
oc get deployment lsd-genai-playground -n card-scout-dev
# Inspect service status.
oc get service lsd-genai-playground-service -n card-scout-dev
# Inspect the model pods and their readiness.
oc get pods -n card-scout-dev
# Inspect the trace service’s readiness and web URL.
oc get mlflow mlflow -o json | jq '{conditions:.status.conditions,url:.status.url}'
----

Continue only when the backend is Ready in `card-scout-dev`. A Playground created in another project does not provide the application endpoint. The first Red Hat image pull can take several minutes; inspect `oc describe ogxserver lsd-genai-playground -n card-scout-dev` and pod events if a wait times out.

The operator manages a 1 GiB persistent volume for the bundled SQLite/FAISS storage. The built-in Responses provider requires the vector storage providers at startup, so they remain in the configuration even though Card Scout does not use document retrieval. The agent trusts the OpenShift AI CA bundle and verifies the MaaS HTTPS certificate; no custom startup command or TLS bypass is needed. Card Scout stores analysis and research results in a separate persistent volume. OpenShift AI's Playground is used later to test the prepared agent, not to provision it.

The runtime application calls:

[source,text]
----
http://lsd-genai-playground-service.card-scout-dev.svc.cluster.local:8321/v1/responses
model: maas-vllm-inference-1/deepseekv4pro
----

The NetworkPolicy applied below permits the Dev Spaces namespaces to reach only the native API port (8321), without editing the operator-owned policy or opening its metrics port.

This is the native OpenShift AI agent backend. OpenCode uses the MaaS Chat Completions endpoint for coding; the app uses Responses for model/tool turns. Both reach the same DeepSeek deployment, with separate MaaS credentials.

[IMPORTANT]
====
*Allow 3–10 minutes for the initial agent image and startup.* The OGX status wait
and rollout check each allow 10 minutes. Wait for `Ready` in *card-scout-dev*, not
in an arbitrary project. If the Service is absent, the backend is not ready:
inspect this OGXServer and its pod events before running the configuration helper.
====

== Create application resources

Apply the manifests for the app identity, service CA, image-pull permissions, MaaS subscription and Dev Spaces network access:

include::ROOT:partial$run-cluster.adoc[]

[source,sh,role=execute]
----
# Create app identity, storage, subscription and workspace network access.
oc apply -k deploy/card-scout/access
# Wait until the requested token-allowance subscription is usable.
oc wait maassubscription/deepseekv4pro-card-scout -n models-as-a-service \
  --for=condition=Ready --timeout=180s
# Check the created resources and their status.
oc get serviceaccount,pvc -n card-scout-dev
----

== Configure the prepared service

A helper handles the dynamic MaaS key and MLflow experiment APIs. The CLI then
applies the service manifests. Its prebuilt Red Hat UBI image includes the fixed
dataset and all 105 images; the lab does not download card images at startup.

include::ROOT:partial$run-cluster.adoc[]

[source,sh,role=execute]
----
# Configure the native-agent API, runtime MaaS key, dataset and MLflow experiment.
python3 scripts/prepare-card-scout.py
# Deploy the prepared dataset/API service; this is distinct from the generated Go app.
oc apply -k deploy/card-scout
# Wait for the deployment to become available.
oc rollout status deployment/card-scout-platform -n card-scout-dev --timeout=600s
# Inspect service status.
oc get service card-scout-platform -n card-scout-dev
# Check the created resources and their status.
oc get pvc card-scout-data -n card-scout-dev
# Inspect configmap status.
oc get configmap card-scout-config -n card-scout-dev -o json | jq .data
# Confirm the named Secret exists; this command does not decode or print its credentials.
oc get secret card-scout-model -n card-scout-dev
----

The platform service owns the runtime model key, state and trace export. Its
service account receives MLflow integration access, with no monitoring or
workload-editing grant.

[TIP]
====
The runtime MaaS key expires after 24 hours. If the agent's model access expires,
renew it in the *cluster terminal*:

[source,sh,role=execute]
----
# Configure the native-agent API, runtime MaaS key, dataset and MLflow experiment.
python3 scripts/prepare-card-scout.py
# Restart the app pods to load the renewed configuration or newly pushed image.
oc rollout restart deployment/card-scout-platform -n card-scout-dev
# Wait for the deployment to become available.
oc rollout status deployment/card-scout-platform -n card-scout-dev --timeout=180s
----
====

The generated Go app has no model key, Kubernetes token or storage volume. It
calls one internal API supplied as `CARD_SCOUT_URL`. Its delivery scaffold uses
`APP_NAME=card-scout`, with `card-scout-build` and `card-scout-dev` namespaces.

== Check the fixed dataset

include::ROOT:partial$run-cluster.adoc[]

[source,sh,role=execute]
----
# Read the prepared Card Scout service’s Route hostname.
CARD_HOST=$(oc get route card-scout-tools -n card-scout-dev -o jsonpath='{.spec.host}')
# Read the real dataset and persisted analysis progress from the prepared service.
curl --fail-with-body -sS "https://${CARD_HOST}/api/batch" |   jq '{dataset,running,completed,failed,first:.items[0]}'
----

Expect all *102 English Base Set cards (1999)*, using 1st Edition scans:
69 Pokémon, 26 Trainers and seven Energy cards. There are 38 Common, 32 Uncommon
and 32 Rare cards. Add three negative controls: a standalone Pikachu illustration,
a Yu-Gi-Oh! card and Magic Black Lotus. The complete batch has 105 images.
Controls belong under *Other* and must not offer a Pokémon price check.

D3 reads the small bottom-right rarity mark. A circle means Common, a diamond
Uncommon, and a star Rare. A square tilted 45 degrees is the diamond. Basic Energy cards
are Common even without a printed rarity symbol. The 1st Edition stamp describes
the print run, not the rarity. Source catalogue references are known; D3 sees
only image bytes, with labels held out. It does not authenticate physical cards
or establish their condition. Provider aggregate prices must not be presented
as verified 1st Edition quotes.

image::card-scout-workflow.svg["Analyze the fixed batch, then verify a selected card through the native agent and MCP",align="center",link=self]

The price tool looks up the selected dataset reference and retains provider,
currency, update timestamp and variant information. The agent must call it before
answering. Displayed amounts come from that evidence, never from model prose.
A rare card is not necessarily valuable; a market aggregate is not a sale offer.

The public MCP endpoint and app have no extra login. The OpenShift AI Playground
still uses its normal OpenShift session and MaaS subscription.
