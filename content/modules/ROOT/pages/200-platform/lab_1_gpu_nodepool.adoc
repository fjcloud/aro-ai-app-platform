= Lab 1.1 — Publish DeepSeek on Foundry

Act 1 starts here. Publish *DeepSeek-V4 Pro* as a managed endpoint on Microsoft Foundry. OpenCode calls that endpoint this afternoon. This workshop does not add a GPU node, and it does not load a model onto the cluster.

[NOTE]
====
*Estimated time:* 15 minutes +
*Persona:* Platform Engineer +
*Blocking:* Lab 1.3 reads `state/foundry.env` from this lab. Stay in this shell until the curl returns a sentence.
====

[IMPORTANT]
====
This is Global Standard, pay per token, in East US 2. DeepSeek-V4 Pro is *$1.74 per million input tokens* and *$3.48 per million output tokens*. Cached input is $0.145 per million. An idle deployment costs nothing. Reasoning tokens are billed as output. Delete the deployment at the end of the day (Lab 3.1).
====

== What you are creating

[cols="1,2", options="header"]
|===
| Setting | Value

| Foundry account
| `arodeepseek<lab-suffix>` in the lab resource group, kind `AIServices`, East US 2

| Deployment
| `deepseekv4pro`

| Model
| `DeepSeek-V4-Pro`, format `DeepSeek`, version `2026-04-23`

| SKU
| `GlobalStandard`, capacity `1`
|===

The login script does not export `SUBSCRIPTION` or `RESOURCEGROUP`. Read them from Azure.

== Create the account and the deployment

[source,sh,role=execute]
----
SUBSCRIPTION=$(az account show --query id -o tsv)
RESOURCEGROUP=$(az group list --query "[?starts_with(name, 'openenv-')].name | [0]" -o tsv)
SUFFIX="${RESOURCEGROUP#openenv-}"
FOUNDRY_NAME="$(printf 'arodeepseek%s' "$SUFFIX" | tr -cd '[:alnum:]')"
API=2025-06-01
DEPLOYMENT=deepseekv4pro
LOCATION=eastus2

az rest --method put \
  --url "https://management.azure.com/subscriptions/${SUBSCRIPTION}/resourceGroups/${RESOURCEGROUP}/providers/Microsoft.CognitiveServices/accounts/${FOUNDRY_NAME}?api-version=${API}" \
  --body "{\"location\":\"${LOCATION}\",\"kind\":\"AIServices\",\"sku\":{\"name\":\"S0\"},\"properties\":{\"customSubDomainName\":\"${FOUNDRY_NAME}\",\"publicNetworkAccess\":\"Enabled\"}}"

until [[ "$(az rest --method get \
  --url "https://management.azure.com/subscriptions/${SUBSCRIPTION}/resourceGroups/${RESOURCEGROUP}/providers/Microsoft.CognitiveServices/accounts/${FOUNDRY_NAME}?api-version=${API}" \
  --query "properties.provisioningState" -o tsv)" == "Succeeded" ]]; do
  sleep 10
done

az rest --method get \
  --url "https://management.azure.com/subscriptions/${SUBSCRIPTION}/resourceGroups/${RESOURCEGROUP}/providers/Microsoft.CognitiveServices/accounts/${FOUNDRY_NAME}/models?api-version=${API}" \
  --query "value[?name=='DeepSeek-V4-Pro'].{name:name,format:format,version:version,sku:skus[0].name}" -o table
----

The table should show format `DeepSeek`, version `2026-04-23`, SKU `GlobalStandard`. Then create the deployment:

[source,sh,role=execute]
----
az rest --method put \
  --url "https://management.azure.com/subscriptions/${SUBSCRIPTION}/resourceGroups/${RESOURCEGROUP}/providers/Microsoft.CognitiveServices/accounts/${FOUNDRY_NAME}/deployments/${DEPLOYMENT}?api-version=${API}" \
  --body '{"sku":{"name":"GlobalStandard","capacity":1},"properties":{"model":{"format":"DeepSeek","name":"DeepSeek-V4-Pro","version":"2026-04-23"}}}'

until [[ "$(az rest --method get \
  --url "https://management.azure.com/subscriptions/${SUBSCRIPTION}/resourceGroups/${RESOURCEGROUP}/providers/Microsoft.CognitiveServices/accounts/${FOUNDRY_NAME}/deployments/${DEPLOYMENT}?api-version=${API}" \
  --query "properties.provisioningState" -o tsv)" == "Succeeded" ]]; do
  sleep 10
done
----

== Test it

The key stays in the shell variable. Do not paste it into the chat or the workshop repo.

[source,sh,role=execute]
----
ENDPOINT=$(az rest --method get \
  --url "https://management.azure.com/subscriptions/${SUBSCRIPTION}/resourceGroups/${RESOURCEGROUP}/providers/Microsoft.CognitiveServices/accounts/${FOUNDRY_NAME}?api-version=${API}" \
  --query "properties.endpoint" -o tsv)
ENDPOINT="${ENDPOINT%/}/"
KEY=$(az rest --method post \
  --url "https://management.azure.com/subscriptions/${SUBSCRIPTION}/resourceGroups/${RESOURCEGROUP}/providers/Microsoft.CognitiveServices/accounts/${FOUNDRY_NAME}/listKeys?api-version=${API}" \
  --query key1 -o tsv)

curl -sS --max-time 180 "${ENDPOINT}openai/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "api-key: ${KEY}" \
  -d '{"model":"deepseekv4pro","messages":[{"role":"user","content":"Reply with one short sentence."}],"max_completion_tokens":512}'

mkdir -p state
cat > state/foundry.env << EOF
SUBSCRIPTION=${SUBSCRIPTION}
RESOURCEGROUP=${RESOURCEGROUP}
FOUNDRY_NAME=${FOUNDRY_NAME}
DEPLOYMENT=${DEPLOYMENT}
API=${API}
ENDPOINT=${ENDPOINT}
EOF
----

The answer is in `choices[0].message.content`. `state/foundry.env` has no key. Lab 1.3 reads the key again from Azure.
