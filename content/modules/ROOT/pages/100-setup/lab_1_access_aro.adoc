= Act 0 — Get in

Your assigned RHDP environment already contains an ARO cluster and a bastion with a WeTTY browser terminal. This lab connects to that cluster; it does not deploy another one.

[NOTE]
====
*Estimated time:* 10 minutes +
*Persona:* Platform Engineer +
*Blocking:* Act 1 requires a classic ARO cluster on OpenShift 4.21 or later, Ready workers, cluster-admin access, and Azure permissions for Foundry and the extra GPU/CPU workers. Check T4 quota and regional capacity with the facilitator before Act 1.
====

== Open your environment

. Sign in to https://demo.redhat.com[Red Hat Demo Platform] and open the assigned environment.
. Use the *workshop ID, assigned email, and workshop password* supplied by your facilitator.
. Open https://fjcloud.github.io/cloud-terminal-pages/[Cloud Terminal], choose *Azure · AI developer platform on ARO*, enter those details, and click *Open workshop*. The launcher retrieves your assigned Showroom URL automatically.

The guide opens beside the existing terminal. Use *Open in new tab* and the environment's supplied access details if the terminal does not appear or requires a login. RHDP controls the environment's lifetime.

== Log in

Use the Azure identity and OpenShift access instructions supplied with this environment. Do not replace its cluster credentials or create another ARO cluster. If `oc` is not logged in, open the existing cluster console and use *Copy login command* from your user menu.

[source,sh,role=execute]
----
az account show --query '{subscription:id, identity:user.name}' --output table
oc whoami
oc get nodes
oc auth can-i '*' '*' --all-namespaces
oc whoami --show-console
----

The permission check must return `yes` and the workers must be Ready. The platform operators require a compatible OpenShift version; the facilitator must validate the chosen RHDP environment before distributing access.

== Clone the workshop

[source,sh,role=execute]
----
cd "$HOME"
git clone https://github.com/fjcloud/aro-ai-app-platform.git
cd aro-ai-app-platform
make onboard
----

The check reads the existing Azure and cluster identities and worker readiness. It does not create identities, fetch a new pull secret, or provision a cluster. Keep this directory for the later `oc apply -k deploy/...` commands.

Before Lab 1.1, obtain the exact *assigned Azure resource group* from RHDP. Export it as `RESOURCEGROUP`. Foundry resources must be created in that group; do not select the first group in the subscription. The Azure identity needs permission to create those resources and access the model.

[source,sh,role=execute]
----
export RESOURCEGROUP="<assigned-resource-group>"
az group show --name "$RESOURCEGROUP" --query '{name:name,location:location}' -o table
----

For example, use `openenv-<your-lab-guid>` only when that exact name appears in your RHDP assignment.
