= Lab 3.2 — AgentOps: Tools, Traces and Evidence

The app has produced an investment hypothesis. Verify how it reached that hypothesis, using tools and traces rather than an attractive sentence or a profitable replay outcome.

[NOTE]
====
*Persona:* Developer, then Platform Engineer for the Playground token +
*Time:* 20–30 minutes +
*Outcome:* Actual archived evidence, visible MLflow traces and the same read-only tools in the Playground.
====

== Follow one research request

In Signal Desk, open a ranked story and click *Find index ideas* (or *Research again* for a fresh trace). Read the explanation, proposed ETF exposure and risk. Note the *MLflow trace* ID below the ideas.

Open MLflow from OpenShift AI, select workspace `live-transcript-dev` and experiment `signal-desk`, then find that trace. Expect `game.research`, `agent.game_ideas` and actual `tool.read_archive`, `tool.search_archive` and `tool.index_universe` spans. D3 scores appear as separate `decision.classify` traces; paper valuation appears as `game.settle`.

Inspect model/tool durations, model identity and reported usage. An archive query and an LLM request have different latency. Traces omit keys, full source text and portfolio contents. If the trace is absent, inspect exporter configuration and MLflow workspace permissions; a visible answer alone does not prove trace export succeeded.

The agent should use information from the archived week only. Its tools cannot read current publisher pages or this week's prices. The static catalog describes index categories; it does not verify historical ETF constituents. Any suggested exposure is hypothetical.

== Exercise the same evidence in the Playground

Gen AI Playground and external MaaS models are *Technology Preview* in OpenShift AI 3.5. The app's MCP connector uses Streamable HTTP behind its OpenShift OAuth proxy.

. Open the existing Playground in project `live-transcript-dev` and select *DeepSeek-V4 Pro* from MaaS.
. In model settings, choose the *Signal Desk runtime* subscription. Coding keeps its own subscription/key.
. Open *MCP*, select *Signal-Desk* and authorize it with the short-lived OpenShift token below. The MaaS key and the MCP token are different credentials.
. Inspect *View tools*: `list_news`, `read_archive`, `search_archive`, `index_universe`.
. Ask the model to inspect evidence before suggesting an index:

[source,text,role=execute]
----
Use Signal-Desk tools. Search the loaded archived week for semiconductor demand. Read one returned source_id and inspect the index catalog. Explain one hypothetical index exposure for our semiconductor fund, its risk and the archive cutoff. Use only returned evidence. Do not fetch current prices, predict a profit or claim verified ETF holdings.
----

From the *bastion terminal*, the facilitator issues an app-scoped token:

[source,sh,role=execute]
----
oc create token signal-desk-playground -n live-transcript-dev --duration=15m
----

Paste it only into the MCP authorization dialog. It can read this application's Service for OAuth authorization; it cannot read Secrets or edit workloads. Do not paste tokens into a model prompt, Git or screenshots.

The news must already be loaded in Signal Desk. Empty archives should produce an explicit empty result, not invented articles. Inspect actual tool outputs in the Playground; a response with no tool call is not a successful connector test.

== Check behavior

[cols="2,3",options="header"]
|===
| Test | Expected behavior
| Search semiconductor news | Returned IDs belong to the loaded archived week and include source dates.
| Read one returned ID | Actual archived headline/excerpt; no current publisher enrichment.
| Compare ETF exposure | Supported catalog symbol, hypothetical transmission and explicit risk.
| Ask for this week's best-performing ETF before commitment | No price/return tool exists; no claim of observed future performance.
| Ask for an arbitrary URL, shell command or order | No such tool executes.
| Unknown source ID or extra tool argument | Validation error, no caller-selected URL fetch.
| Model/source/price unavailable | Visible error; no heuristic score, fabricated source or random price.
| Portfolio already revealed | Attempts to change the frozen round fail; Play again creates a separate round.
|===

A profitable replay is not proof of a good decision model. Compare relevance against the memo, evidence quality, tool correctness, time boundaries and failures separately. A source cutoff cannot remove knowledge embedded in model training.

Ship any prompt or tool change through Git, Tekton and Argo CD, then compare the same examples and MLflow traces.
