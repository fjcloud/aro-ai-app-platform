= Lab 3.2 — AgentOps: Tools, Traces and Evidence

The app has produced an investment hypothesis. Verify how it reached that hypothesis, using tools and traces rather than an attractive sentence or a profitable replay outcome.

[NOTE]
====
*Persona:* Developer +
*Time:* 20–30 minutes +
*Outcome:* Actual archived evidence, visible MLflow traces and the same read-only tools in the Playground.
====

== Follow one research request

In Signal Desk, open a ranked story and click *Find stock opportunities* (or *Research again* for a fresh trace). Read the explanation, proposed company, business relationship and risk. Click *View MLflow trace* to open that exact research and its graph. Expand *Show reasoning & sources* for the full explanation and finance skill provenance. *Research again* is inside that section.

The link selects workspace `signal-desk-dev`, experiment `signal-desk` and the trace automatically. Open *Details & Timeline* and its *Graph* to follow the calls. Expect `game.research`, `agent.game_ideas` and actual `tool.read_archive`, `tool.search_archive`, `tool.search_web`, `tool.read_web` and `tool.search_companies` spans, separated by `llm.research.*` calls. D3 scores appear as separate `decision.classify` traces; paper valuation appears as `game.settle`.

For a new research, check the root span attributes `research.skill.name` and `research.skill.upstream_revision`: they identify the bundled Anthropic idea-generation adaptation actually supplied to DeepSeek. The skill adds a method, not training or new market data.

Select each tool node and inspect *Inputs / Outputs*: search queries, source IDs, eligible sources, excluded results and their reasons, publisher coverage/errors and actual excerpts. Each `llm.research.*` node shows the request payload and visible model response, including function calls and the final answer. Provider headers, keys and hidden reasoning blocks are excluded. Search results excluded by date are retained in the audit, not sent back to the model.

Inspect model/tool durations, model identity and reported usage. An archive query and an LLM request have different latency. Traces omit keys, full source text and portfolio contents. If the trace is absent, inspect exporter configuration and MLflow workspace permissions; a visible answer alone does not prove trace export succeeded.

The agent uses archived news and public web sources dated at or before the saved cutoff. Company lookup returns current names, tickers and exchanges, without prices or historical fundamentals. Web search rejects undated and newer results. Publisher text is used only with eligible publication/modification metadata; blocked, changed or undated pages use the explicitly dated search excerpt. Neither a search-index date nor a current fetch proves that the page is an unchanged historical snapshot. There is no market-price tool. News facts stay within the saved cutoff; proposed business links and benefits remain hypotheses unless supported by the archived sources.

=== 4. Ask a question and inspect the evidence

The Playground validates one component at a time. Its native loop does not enforce the app’s staged tool protocol. Use the supplied short system prompt and start with this single-tool probe:

[source,text,role=execute]
----
Use the search_web tool exactly once with query "SK Hynix memory demand". Summarize two returned eligible headlines and their dates. Stop after this one tool call.
----

For another component probe, start a new chat and request `search_archive` or `search_companies` once. Keep the full research workflow in the application, where tool order and limits are enforced.

image::signal-desk-playground-answer.png["A real Playground response to a single-tool component probe"]

Expand *Tool response* below each answer. Verify the actual requested call, source IDs, date cutoff and company identity. These probes establish model/MCP connectivity. The complete app research, including page reads, finance skill and final hypothesis, is validated through its direct MLflow trace.

This tests the model, instructions and MCP tools directly in OpenShift AI. The app's research button uses the same model and read-only evidence through its bounded Responses loop. To inspect the app's MLflow spans, use *Research again* in Signal Desk and open its direct trace link as described above.

Empty archives should produce an explicit empty result, not invented articles. A response with no tool call is not a successful connector test.

== Check behavior

[cols="2,3",options="header"]
|===
| Test | Expected behavior
| Search semiconductor news | Returned IDs belong to the loaded archived week and include source dates.
| Read one returned ID | Actual archived headline/excerpt; no current publisher enrichment.
| Compare company opportunities | Verified company ticker, direct/supplier/customer/competitor relationship, sourced catalyst and explicit risk.
| Ask for this week's best-performing stock before commitment | No price/return tool exists; no claim of observed future performance.
| Ask for an arbitrary URL, shell command or order | No such tool executes.
| Unknown source ID or extra tool argument | Validation error, no caller-selected URL fetch.
| Model/source/price unavailable | Visible error; no heuristic score, fabricated source or random price.
| Portfolio already revealed | Attempts to change the frozen round fail; Try another story creates a separate round.
|===

A profitable replay is not proof of a good decision model. Compare relevance against the memo, evidence quality, tool correctness, time boundaries and failures separately. A source cutoff cannot remove knowledge embedded in model training.
